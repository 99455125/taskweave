## 任务变量规则

合约编号和名称后缀使用可配置前缀和时区，时间戳格式目前固定为 `YYYYMMDDHHMMSS`。同次执行只生成一次时间戳，录入与查重复用该值。示例历史编号不能作为新运行的默认值；查询发现重复时停止，不能通过重新新建绕过。

合约类型、主险类、参与方数组、分项数组、账单参数和附件路径应由变量提供。每个分项独立配置险种列表、金额和手续费。用户后续提供业务规则时调整这些变量和对应步骤说明；只有一个步骤使用的变量保留在该步骤，共享变量才放在任务级。前序步骤产生的平台编号通过结果绑定传递，不要求用户预先输入。

图片验证码使用 OCR 插件读取实际图片并填写，再验证登录结果；识别出的文字不能固化为代码常量。识别为空、格式不符或登录失败时明确报错并提供人工接管，不无限刷新。使用电脑控制工具识别新验证码时遵守工具的当次确认要求。邮箱验证码通过专用变量 `uat_email_code` 提供，固定测试值仅用于本 UAT 环境。

## 录入和验证顺序

1. 打开登录页并切换中文，完成图片和邮箱验证，检查实际进入首页及分出机构身份。
2. 进入合约交易管理的合约列表，按本次编号查重；新增时选择财产保险和比例再保险。
3. 填写成数合约基本信息及账单条件，检查日期、币种和金额。
4. 搜索并选择两个再保机构，填写 70% 和 30%，检查均未设置首席。
5. 为双方上传测试合同，检查页面真实附件下载链接。
6. 新建两个分项，各选择家庭财产保险和机动车辆保险，填写限额、固定手续费率及损失分摊设置。
7. 保存并检查进入编辑页，记录平台生成的编号；核对已锁定的业务年度和期间。
8. 选择确认并提交审核，填写 UAT 测试意见；返回列表按本次编号查询，应只有一条记录。
9. 打开处理页，检查进入合约审核和业务字段只读，结束录入流程。

上述是业务操作顺序。实际任务9步将中文切换与登录分开，将参与方与附件合并；按可独立调试和验证的边界组织，无需每个点击生成一个步骤。

## 合约类型的页面差异

成数合约的分项包含类别、险种、保额币种、最大承保限额、手续费类型和损失分摊标志。切换溢额合约或混合比例合约时，页面还显示溢额线数、最大净自留额、最大毛自留额、成数分出份额和分出承保能力；切回成数后这些字段消失。

固定手续费显示固定手续费率；浮动手续费显示预付手续费率及上下限。上述差异来自实际页面观察。溢额、混合比例及浮动手续费的必填校验和保存流程尚未验证，不能按本次成数合约成功结果宣称全部类型可自动录入。
