# routes_task_file.py 接口文档

本文档详细描述了 `routes_task_file.py` 文件中实现的所有API接口。这些接口主要用于管理与任务关联的Excel文件。

**重要说明：** 所有文件操作接口现在都会处理上传的 Excel 文件中的 **所有工作表 (sheets)**。每个工作表都会在数据库中创建一张对应的表，表名通常以 `文件名_工作表名` 的形式生成。

## 任务文件管理接口

### 1. 上传任务文件

为指定的任务上传一个新的Excel文件。上传成功后，文件中 **所有工作表** 的内容都将被解析，并在任务对应的数据库中为每个工作表创建一张表。

**请求URL：** `/tasks/{task_id}/files`

**请求方式：** POST

**路径参数：**
- `task_id`: (Integer, 必填) 文件要关联的任务ID。

**请求体 (multipart/form-data)：**
- `file`: (File, 必填) 要上传的Excel文件。仅支持 `.xlsx` 格式。

**响应示例 (成功 - Excel包含两个工作表: Sheet1, Sheet2)：**
```json
{
  "code": 200, // 注意：根据您的代码，成功码通常是 200
  "message": "文件上传成功", // 注意：根据您的代码，成功消息通常是 "文件上传成功"
  "data": {
    "taskFileId": 1,
    "taskId": 1,
    "fileName": "data.xlsx",
    "taskTables": [
      {
        "tableId": 1,
        "tableName": "data_Sheet1", 
        "taskId": 1,
        "taskFileId": 1,
        "stepId": null,
        "tableColumn": "[\"column1\",\"column2\",\"column3\"]", // JSON 字符串格式
        "tablePreviewJson": "{\"columns\": [\"业务员名称\", \"业务员代码\", \"所属地区\"], \"data\": [{\"业务员名称\": \"王丽\", \"业务员代码\": \"G01\", \"所属地区\": \"上海\"}, {\"业务员名称\": \"王二丽\", \"业务员代码\": \"G02\", \"所属地区\": \"上海\"}, {\"业务员名称\": \"王三丽\", \"业务员代码\": \"G03\", \"所属地区\": \"北京\"}, {\"业务员名称\": \"王四丽\", \"业务员代码\": \"G04\", \"所属地区\": \"北京\"}]}"
      },
      {
        "tableId": 2,
        "tableName": "data_Sheet2", 
        "taskId": 1,
        "taskFileId": 1,
        "stepId": null,
        "tableColumn": "[\"colA\",\"colB\"]", // JSON 字符串格式
        "tablePreviewJson": "{\"columns\": [\"业务员名称\", \"业务员代码\", \"所属地区\"], \"data\": [{\"业务员名称\": \"王丽\", \"业务员代码\": \"G01\", \"所属地区\": \"上海\"}, {\"业务员名称\": \"王二丽\", \"业务员代码\": \"G02\", \"所属地区\": \"上海\"}, {\"业务员名称\": \"王三丽\", \"业务员代码\": \"G03\", \"所属地区\": \"北京\"}, {\"业务员名称\": \"王四丽\", \"业务员代码\": \"G04\", \"所属地区\": \"北京\"}]}"
      }
    ]
  }
}
```

**说明：**
- 任务状态必须为非“执行中”（`task_status != '02'`）。
- 文件必须是 `.xlsx` 格式。
- 系统会处理上传Excel文件的 **所有工作表**。
- **表名生成规则**：为每个工作表创建的数据库表名格式为 `文件名(去除后缀)_工作表名` (例如，文件 `data.xlsx` 中的工作表 `Sheet1` 会生成表 `data_Sheet1`)。
- **工作表名称校验**：Excel 文件内部不允许存在重复的工作表名称。
- **表名唯一性校验**：生成的每个表名在所属任务内必须唯一。如果已存在同名表，上传会失败。
- 会为上传的文件创建一个 `TaskFile` 记录。
- 会为每个工作表创建一个 `TaskTable` 记录，包含表名、列信息和数据预览。
- `tableColumn`: (String) 一个包含列名数组的JSON字符串。
- `tablePreviewJson`: (String) 一个包含前10行数据的JSON字符串。

**错误响应示例：**
```json
{
  "code": 500, // 或其他错误码
  "message": "任务不存在"
}
```
```json
{
  "code": 500,
  "message": "任务执行中，无法上传文件"
}
```
```json
{
  "code": 500,
  "message": "没有上传文件"
}
```
```json
{
  "code": 500,
  "message": "仅支持.xlsx格式的Excel文件"
}
```
```json
{
  "code": 500,
  "message": "Excel文件中存在重复的工作表名称，请修改后重新上传"
}
```
```json
{
  "code": 500,
  "message": "任务下已存在相同的表名: [文件名_工作表名]"
}
```
```json
{
  "code": 500,
  "message": "处理Excel文件失败: [具体错误信息]"
}
```

### 2. 获取任务的文件列表

**请求URL：** `/tasks/{task_id}/files`

**请求方式：** GET

**路径参数：**
- `task_id`: (Integer, 必填) 任务ID。

**响应参数说明 (data数组中每个TaskFile对象)：**
- `taskFileId`: (Integer) 任务文件的ID。
- `taskId`: (Integer) 所属任务的ID。
- `fileName`: (String) 上传的文件名。
- `taskTables`: (Array) 包含此文件所有工作表关联的表信息。
    - `tableId`: (Integer) `TaskTable` 的ID。
    - `tableName`: (String) 表名 (格式: `文件名_工作表名`)。
    - `taskId`: (Integer) 所属任务的ID。
    - `taskFileId`: (Integer) 所属任务文件的ID。
    - `stepId`: (Integer, nullable) 关联的步骤ID (对于文件上传产生的表，此项为null)。
    - `tableColumn`: (String) 包含列名数组的JSON字符串。
    - `tablePreviewJson`: (String) 表数据预览 (JSON格式字符串)。

**错误响应示例 (任务不存在)：**
```json
{
  "code": 500,
  "message": "任务不存在"
}
```

### 4. 更新文件（上传新版本）

为指定的 `task_file_id` 上传一个新的Excel文件版本。**文件名必须与原文件名相同。** 旧文件关联的所有物理表会被删除，并根据新文件 **所有工作表** 的内容重新创建或更新对应的表。

**请求URL：** `/task-files/{task_file_id}`

**请求方式：** PUT

**路径参数：**
- `task_file_id`: (Integer, 必填) 要更新的任务文件的ID。

**请求体 (multipart/form-data)：**
- `file`: (File, 必填) 新版本的Excel文件。仅支持 `.xlsx` 格式。**文件名必须与原文件一致。**

**响应示例 (成功)：**
```json
{
  "code": 200,
  "message": "文件更新成功",
  "data": {
    "taskFileId": 1,
    "taskId": 1,
    "fileName": "data.xlsx", // 文件名保持不变
    "taskTables": [
      {
        "tableId": 1, // 可能复用旧 tableId，也可能变化，取决于实现
        "tableName": "data_Sheet1", 
        "taskId": 1,
        "taskFileId": 1,
        "stepId": null,
        "tableColumn": "[\"new_col1\",\"new_col2\"]",
        "tablePreviewJson": "{\"columns\": [\"业务员名称\", \"业务员代码\", \"所属地区\"], \"data\": [{\"业务员名称\": \"王丽\", \"业务员代码\": \"G01\", \"所属地区\": \"上海\"}, {\"业务员名称\": \"王二丽\", \"业务员代码\": \"G02\", \"所属地区\": \"上海\"}, {\"业务员名称\": \"王三丽\", \"业务员代码\": \"G03\", \"所属地区\": \"北京\"}, {\"业务员名称\": \"王四丽\", \"业务员代码\": \"G04\", \"所属地区\": \"北京\"}]}"
      },
      {
        "tableId": 3, // 新增的工作表会得到新的 tableId
        "tableName": "data_NewSheet", 
        "taskId": 1,
        "taskFileId": 1,
        "stepId": null,
        "tableColumn": "[\"extra_col\"]",
        "tablePreviewJson": "{\"columns\": [\"业务员名称\", \"业务员代码\", \"所属地区\"], \"data\": [{\"业务员名称\": \"王丽\", \"业务员代码\": \"G01\", \"所属地区\": \"上海\"}, {\"业务员名称\": \"王二丽\", \"业务员代码\": \"G02\", \"所属地区\": \"上海\"}, {\"业务员名称\": \"王三丽\", \"业务员代码\": \"G03\", \"所属地区\": \"北京\"}, {\"业务员名称\": \"王四丽\", \"业务员代码\": \"G04\", \"所属地区\": \"北京\"}]}"
      }
    ]
  }
}
```

**说明：**
- 任务状态必须为非“执行中”（`task_status != '02'`）。
- 新文件必须是 `.xlsx` 格式。
- **文件名校验**：上传的新文件名必须与 `TaskFile` 记录中的原文件名一致，不允许通过此接口修改文件名。
- **工作表名称校验 (新文件内部)**：新 Excel 文件内部不允许存在重复的工作表名称。
- **列名兼容性校验**：对于新文件中与旧文件同名（`文件名_工作表名`）的工作表，其列名必须包含旧版本该工作表的所有列名（旧列是新列的子集）。
- **新增工作表表名校验**：如果新文件包含旧文件中没有的工作表，会为其生成新的表名 (`文件名_新工作表名`)，并校验该表名在任务中是否已存在（不包括当前文件自身原有的表）。
- `TaskFile` 记录的 `file_name` 保持不变。
- 原 `TaskFile` 关联的所有 `TaskTable` 记录对应的物理表会被删除。
- 根据新Excel文件的 **所有工作表**，重新创建或更新物理表，并相应创建或更新 `TaskTable` 记录的 `table_column` 和 `table_preview_json`。

**错误响应示例：**

```json
  "message": "任务执行中，无法更新文件"
}
```
```json
{
  "code": 500,
  "message": "文件名不允许更新，请重新上传"
}
```
```json
{
  "code": 500,
  "message": "仅支持.xlsx格式的Excel文件"
}
```
```json
{
  "code": 500,
  "message": "Excel文件中存在重复的工作表名称，请修改后重新上传"
}
```
```json
{
  "code": 500,
  "message": "工作表 [sheet_name] 的列名与原始文件不匹配，请检查后重新上传"
}
```
```json
{
  "code": 500,
  "message": "任务下已存在相同的表名: [文件名_新工作表名]"
}
```
```json
{
  "code": 500,
  "message": "更新文件失败: [具体错误信息]"
}
```

### 5. 删除文件

删除指定的任务文件、其关联的所有 `TaskTable` 记录以及这些表对应的所有物理数据库表。如果这些表被任务中的步骤使用，相关的后续步骤数据也会被清理。

**请求URL：** `/task-files/{task_file_id}`

**请求方式：** DELETE

**路径参数：**
- `task_file_id`: (Integer, 必填) 要删除的任务文件的ID。

**响应示例 (成功)：**
```json
{
  "code": 200,
  "message": "文件删除成功",
  "data": {
    "taskFileId": 1,
    "taskId": 1
  }
}
```

**说明：**
- 任务状态必须为非“执行中”（`task_status != '02'`）。
- 删除操作会删除 `TaskFile` 记录。
- 同时，会删除所有与此 `task_file_id` 关联的 `TaskTable` 记录（即该文件所有工作表对应的表记录）。
- 并且，会删除这些 `TaskTable` 记录对应的所有物理数据库表。
- **步骤影响**：如果被删除文件中的任何表被任务中的步骤所使用，那么从使用这些表的第一个步骤开始，后续所有步骤的数据和状态都将被清理。

**错误响应示例：**
```json
{
  "code": 500,
  "message": "文件不存在"
}
```
```json
{
  "code": 500,
  "message": "任务执行中，无法删除文件"
}
```
```json
{
  "code": 500,
  "message": "删除文件失败: [具体错误信息]"
}
```
