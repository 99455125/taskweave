# Acceptance with visible evidence

Read `describe(kind="operation", identity="review.prepare")` for the live contract. Freeze requirements before the formal run using `review(action="prepare", params=...)`: target_kind/task or sequence, target_id, expected_version (task hash/sequence revision), title and declarative checks. Bind the returned `review_spec_id` at creation. Future edits require a new version/spec; they do not alter past runs.

Each check has an ID, label, source and comparison. Source identifies a step, output and JSON pointer; sequences also require node_id. An execution_path selects one exact branch/loop instance. Without it, loops use the native aggregate, not the last iteration. Use all/any with a nested check for per-item conditions. An empty all passes; an empty any fails, so use a count/existence requirement when empty work must fail. Unvisited branches are NOT_APPLICABLE by default; choose on_skip=missing when the goal requires visiting them. Nested aggregation and skipped values follow actual flow evidence; null is a valid value when the action ran.

Read `review(action="read", params={kind:"run"|"sequence", identity:...})` for compact checks, status and report fingerprint. Select sections, pointer or cursor for more. Read specs through read_spec. Missing/deleted results are missing evidence. A successful worker with failed business checks is not a passing acceptance. An unconfigured check list is UNCONFIGURED. A result written by the same action establishes what it returned; where the goal requires proof of a remote side effect, create a separate observation step using the relevant plugin and bind checks to that observation.

Use `review(action="open", params={kind:..., identity:...})` to open the matching report in the connected workbench. The UI displays the frozen goal/version, status, paths, checks and original result viewers. Only desktop interaction records ACCEPTED/REJECTED. A decision binds the displayed fingerprint and becomes stale when facts change; nonpassing automatic checks require a human acceptance reason. Report run status, automatic status and human status independently.
