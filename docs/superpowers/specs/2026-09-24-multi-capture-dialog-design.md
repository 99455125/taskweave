# 插件上下文连续采集弹窗：补充设计

日期：2026-09-24\
状态：已确认，交由 `taskweave-builder-luna` 实施\
基础规格：[插件上下文多次采集设计](2026-09-24-multi-capture-context-design.md)

## 要解决的问题

当前点“追加采集项”会立即写库、关闭弹窗并重绘页面。连续查看不同下拉框时，用户每次都得重新展开组、打开弹窗、重填参数。项上的“重新采集”又会替换旧项，容易误删先前采集的证据。

目标是在**同一个弹窗中连续采集多项**，检查、调整后按一次“确认保存”。规划页和步骤编写页保持一致；调试页若使用共用的采集入口，也使用同一行为。只改变交互和提交时机，沿用现有组/项存储模型、插件采集与预览契约、AI 顺序规则。

## 用户交互

1. 新建组仍从“采集上下文”进入。已有组的按钮统一叫 **“重新采集”**，打开同一个弹窗，并在本组末尾追加新项；**不替换任何旧项**。去掉每个采集项上的“重新采集此项”。
2. 弹窗顶部编辑组名称、操作说明；已有组固定采集器，新组可选择采集器。保留插件提供的目标实例、表单、`scope`、预览开关和高级 JSON；实例列表可以在弹窗内刷新。核心不按 Playwright、TiDB 分支写表单规则。
3. 弹窗中部按顺序列出本组已有项与本次新采集项。每项可编辑标题、查看内容/预览、上移、下移、删除；删除已有项先在弹窗中标记，允许撤销，本次新项可直接从待保存列表移除。预览归属具体项，不提供组级合成预览。
4. 用户点击 **“采集一项”**：用当前插件参数执行一次采集，把完整 `ContextCollection` 作为一个新项追加到弹窗列表。弹窗保持打开，参数和目标实例保持原值，用户可在目标页面继续操作并再次点击。采集失败时保留全部待保存项和输入值，显示具体错误。
5. 底部只有 **“取消”** 与 **“确认保存”**。确认时一次提交组元数据、项标题/顺序、新项和删除项。新组至少采集一项才能保存；已有组允许删空并保留组。取消放弃所有未提交的数据库变更；浏览器或其他插件的外部操作无法回滚，界面不暗示能回滚。关闭有未保存修改的弹窗时提示会丢弃本次编辑。
6. 保存成功后更新对应上下文组的卡片，保留外层折叠状态和滚动位置；连续采集期间不要整体重绘规划/步骤页面。卡片外保留组摘要、查看与组级排序/删除；项的编辑集中在弹窗内，避免出现两套行为不同的编辑入口。

## 应用与存储边界

- 将“调用采集器”和“写入规划/步骤上下文”拆开。规划侧当前采集操作若直接落库，应增加仅返回采集结果的应用操作；步骤侧复用已有只读采集能力。采集结果先保存在弹窗状态，不进入 AI、草稿或数据库。
- 为规划组、步骤组分别提供**一次事务提交**的应用/仓储操作，输入为组 ID（新组可为空）、预期修订号、组元数据、最终有序项清单、新项内容和已有项删除集合。服务校验组/项归属、采集器一致性、项 ID 与顺序、有效采集结果。一次事务中提交所有变化并递增一次修订号；步骤只触发一次待确认失效。
- 保持插件接口 `collect_context(...)->ContextCollection` 与插件提供的预览渲染不变。核心仅保存和排序一次采集返回的整体结果，不识别插件专有参数。
- 预览按项按需读取。弹窗内新项直接用暂存结果预览；已有项按 ID 读取。展示脱敏、发送 AI 脱敏沿用各自设置，暂存预览也遵守展示脱敏。
- 修订冲突或保存失败时不能部分落库，也不能清空弹窗。保留本次采集与编辑，让用户看到冲突并决定刷新后重试；不静默覆盖另一窗口的改动。避免把大型截图重复塞入列表摘要或页面重绘响应。
- 保存前跳转步骤、调试或 AI 生成，只能读取上次**已提交**的上下文；弹窗未保存内容不能偷偷进入这些流程。

## 定向验收

1. 规划新建 Playwright 组，在一个弹窗中打开页面、采集两次不同展开状态，弹窗未关闭且旧项未丢；确认后得到一个组、两项及分别对应的预览，顺序传给 AI。
2. 已有组点“重新采集”连续新增两项；原项内容、预览与 ID 不变。撤销待删项、删除一个新项、调整顺序后一次保存，结果与弹窗最终列表一致。
3. 取消或关闭未确认弹窗，数据库与 AI 输入不变；插件采集失败和提交冲突不丢失弹窗中的待保存采集。旧组删空后组名称/说明仍在。
4. 步骤页一次确认使已确认步骤变为待确认；规划页修订号按一次提交递增。TiDB/OCR 等采集器无需修改即可使用相同弹窗。
5. 每次采集后不刷新整页，不需重新展开组；确认后保留页面位置与折叠状态。只运行相关服务、仓储和页面组件的定向测试；**不运行全量测试**，除非用户另行确认。

## 实施范围

先检查现有未提交修改并保留。基于当前多次采集实现修改共用上下文组件、规划和步骤采集弹窗、采集应用服务及组级批量提交；按现有 controller/REST 边界接线。删除或停用单项原位替换入口，不做新数据库迁移，不改插件协议、计划生成格式或无关功能。若现有接口无法完成原子提交，补一个批量接口，不用前端串联多个即时保存调用冒充事务。
