# 任务组合串行执行设计

## 目标与范围

用户保存一个有名称的任务组合，自定义已有任务的顺序，一次启动后依次执行。后续任务可通过明确的映射取得任意前序任务的步骤输出；运行详情展示整组进度、各任务结果和需要人工处理的位置。正常且输入齐备时，组合运行无需用户逐项启动。

首版支持线性顺序、同一任务重复出现、任务输入及未绑定的步骤输入映射、手动启动与恢复。定时触发、并行分支、条件跳转、跨组合共享活跃资源及任意文件路径传递不在范围内。单任务运行、任务包和插件 SDK 的现行行为保持兼容。

## 现状依据

一次正式 `Run` 只归属一个任务。`RunUseCases` 创建运行，`CoordinatorPool` 按运行隔离执行实例，`Coordinator` 串行执行任务内步骤。结果仓储只读取同一运行中有效成功尝试的输出。任务内绑定只允许前序步骤且同一运行。现有执行器启动时比对当前任务定义、环境及插件版本；虽保存 `definition_json`，执行仍读取当前任务和步骤。因此组合不能假设子运行可直接执行任意旧快照。

## 方案与职责

建立独立的 `TaskSequence` 定义和 `SequenceRun` 历史，复用现有 `Run` 执行每个节点。定义包含名称、说明、版本、组合输入 Schema 及有序节点。每个节点有稳定的 `node_id`、`task_id`、环境选择、常量输入、组合输入映射和前序输出映射。同一个 `task_id` 可出现在多个节点。

组合用例负责定义校验、启动、查询、控制与恢复决策。组合仓储将定义、运行快照、节点状态和子 `run_id` 存入控制库。后台协调器只负责节点推进，不执行步骤代码；子运行由现有 `RunUseCases` 和 `CoordinatorPool` 完成。presentation 持有组合编辑草稿和异步交互状态，desktop 提供入口、编辑与进度视图；CLI/本地 HTTP 通过应用操作调用同一用例。

## 输入与输出映射

每个目标字段只能有一个来源：常量、组合启动输入，或一个前序节点的输出。输出定位为 `source_node_id + step_id + output_name + JSON Pointer`。目标可为任务输入字段或指定步骤的未绑定输入字段。只接受指向已排在前面的节点；调整顺序时重新校验。组合输入保留 Schema 校验；节点输入在真正创建子运行前使用目标任务和步骤的现行 Schema 校验。`false`、`0`、空字符串及 `null` 作为各自的 JSON 值保留，缺失路径单独报错。

映射通过已有结果读取能力取得有效成功尝试的 JSON `data` 或可确认是 JSON 的命名输出，并记录来源子运行和尝试证据。文件 handler 输出拒绝映射，不转换为跨任务的绝对路径。输出 Schema 可辅助编辑时选择字段，运行时仍检查输出是否存在、指针能否解析及目标类型是否有效。不能读取未完成节点、旧尝试或其他组合运行的结果。预检检查没有依赖前序输出的必填字段；依赖输出的字段延迟到节点启动前校验，映射缺失不回退到默认值。

## 运行生命周期与恢复

启动前预检所有节点、确认状态、静态输入、环境及当前插件。创建组合运行时冻结节点顺序、映射、任务定义指纹、环境指纹及插件版本。每个节点启动前再次核对；定义或环境漂移时阻塞并说明原因，不静默使用新版。创建子运行及写入节点关联使用共享 SQLite UoW：lint 和前置读取可在事务外，事务内重检节点身份及冻结指纹，并以 `(sequence_run_id,node_id)` 唯一约束防重复；提交后才启动 worker。启动命令 ID 和意图先持久化，再调用现有 `run.start`，恢复时先检查回执和子运行事实。重复请求不得创建第二个组合运行或第二个当前子运行。

组合状态为 `READY`、`RUNNING`、`WAITING_INPUT`、`PAUSED`、`BLOCKED`、`SUCCEEDED`、`CANCELLED`；节点状态为 `PENDING`、`RUNNING`、`WAITING_INPUT`、`PAUSED`、`BLOCKED`、`SUCCEEDED`、`CANCELLED`。子运行 `SUCCEEDED` 后解析下一节点输入并自动推进。待补参进入 `WAITING_INPUT`，用户补参后续启原子运行；人工暂停进入 `PAUSED`，显式继续后推进；失败、INTERRUPTED、UNKNOWN、漂移或映射错误进入 `BLOCKED`，按原运行的重试或人工核对规则处理后显式继续；取消进入 `CANCELLED` 并终止本次组合，通用轮询不得续启。容量不足保持待资源状态，不作为业务失败。组合的暂停或取消意图先持久化，在节点切换处再次检查。应用重启先执行现有运行恢复，再核对组合：已成功节点可以继续推进；不确定副作用的子运行需人工核对，不能自动重发。UI 离开不取消已接受运行。

组合拥有的子运行只能通过组合入口发起会影响推进的控制动作；单任务入口不得独立重跑、删除或清理它们。组合入口提供补参、失败重试、UNKNOWN 核对及历史删除。任务删除须检查组合定义引用；子运行及结果删除须检查未删除的组合历史。删除组合历史先在控制库持久化清理意图，再复用现有可恢复删除流程逐项清理控制库、任务数据与文件，最后移除关联；这些存储不构成一个跨文件原子事务。重新运行整个组合会创建新的组合运行；首版不原地重跑已成功的前序节点。

## 交互与兼容

桌面增加“任务组合”入口，可添加/排序任务，配置环境、启动输入与映射，保存并一键运行。运行页显示整体状态、节点顺序、当前待处理原因及子运行详情入口。存在组合必填输入时启动前一次填写。旧数据通过增量 SQLite 迁移保留；独立运行语义不变，受组合管理的运行增加归属保护，并新增组合操作族。任务包格式不扩展到组合定义。

## 验收与验证

- 三个任务按顺序自动完成；可引用非相邻前序节点输出，同任务重复节点保持独立身份。
- 映射缺失、类型错误、非法顺序、任务/环境/插件漂移明确阻塞；`false`、`0`、空字符串及 `null` 不被误判为缺失。
- 重复点击和同请求重放不重复创建或启动；崩溃发生在创建、关联、启动和推进边界时，恢复不重做不确定业务动作。
- 失败、补参、暂停、取消、UNKNOWN 及容量等待均保持准确整体状态；修复后从原节点继续，已成功前序节点不重跑。
- 关闭页面后运行继续；保存定义和历史在重启后可查询；现有单任务运行仍可用。
- 更新存储迁移、操作契约、模块知识和测试映射；运行针对性的应用、仓储、UI 与真实 worker 集成验证。全量测试遵守项目授权规则。
