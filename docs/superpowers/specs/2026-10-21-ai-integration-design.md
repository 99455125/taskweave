# AI 编写、任务调用与可视化验收

## 授权与基线

用户要求完成一版可用的 TaskWeave Skill、MCP 和可视化验收能力，允许扩展必要能力、委托 Astra 设计和审核，只看最终结果。主 Agent 负责实施和集成，沿用当前工作区。前置串行组合及步骤控制流已交接；实施前保存点为 `f2cb96129a6341425c781cea2607fa45a5f9eb9e`。该保存点不包含原有 OCR 元数据和 tmp/。后续提交、推送、PR 或发布不在此授权内。

本设计基于 Astra 的只读研究及交接后源码：公开路由来自 application/operations.py；任务支持顺序、if、foreach、while/until、嵌套和逐实例恢复；线性任务包为 taskweave-task-2，控制流包为 taskweave-task-3。精确参数从当前用例签名及运行时校验获得，不复制旧任务快照。

## 用户路径与完成条件

1. 用户向 AI 描述目标。AI 发现已有任务和插件能力、获取所选材料，创建或修改任务与步骤，保存草稿、校验、试跑、确认正确版本，再执行。外部 AI 编写默认不再次调用内置模型。
2. AI 可直接发现、调用已有任务或串行组合，填写参数并等待有意义的状态变化。流程判断、循环和节点映射在 TaskWeave 内执行，不由 AI 逐轮调度。
3. 用户一次打开对应执行的验收视图，看到目标、版本、实际路径、关键结果、逐项核对和证据。运行状态、自动核对结果和人工验收决定分别呈现。
4. 提供可安装 Skill、可复制 MCP 配置及明确的连接状态；SDK 为可选依赖，默认核心安装不依赖 MCP。
5. 全部十一插件通过实际注册目录按需发现；安装、启用、加载失败和外部环境可用性分开说明。未实际探测外部服务不宣称可运行。

## 方案选择

逐插件动作注册 MCP 会使 AI 重新承担每一步调度，丢失复用收益；原样暴露所有操作和全部 Schema 会增加上下文且泄漏内部数据。采用少量按用途组织的工具，共用 application 用例和有界投影；详细操作契约按需获取。提供同一 JSON 工具契约，供 MCP 或自有 function calling 宿主复用，不引入模型供应商 SDK。

## 分层与运行所有权

- application/agent：发现、编写材料、受限操作、紧凑运行查询和验收服务；不依赖 GUI/MCP/数据库驱动。
- infrastructure：本地连接描述符、鉴权客户端、请求回执与编写材料/验收记录持久化，以及 MCP stdio 适配。数据通过注入端口访问。
- presentation：验收投影与交互状态；desktop 装配实际页面、已有结果渲染器及连接设置。
- packaged Skill：简短入口，按编写、执行、验收逐步加载参考材料，契约从运行服务查询。

每个工作空间只有一个 Application 和协调器。MCP 连接已经运行的 desktop/serve，不能构造第二个 Application。两种启动方式均发布权限受限的本地连接描述符；描述符绑定当前进程和 workspace，关闭时只清理自己的记录。鉴权令牌仅在本机连接层使用，不进入工具返回、日志、URL 或 Skill。未运行时给出可执行启动指引。

## 工具契约与完整能力

按 discover、describe、author、context、execute、wait、inspect、review 组织工具。工具的操作变体为显式白名单，未知操作、额外参数、缺失参数和错误类型在分发前拒绝；详细 handler 参数与默认值来自 build_operation_contracts，参数类型由显式策略声明，未声明类型拒绝公开，业务 Schema 继续由现有用例校验。录制 **options 采用显式参数集合，不开放任意字段。

- discover：按类型、关键词、游标和 limit 查询任务、组合、规划、插件/动作、环境摘要，默认不携带代码、秘密或全部 Schema。
- describe：读取指定对象的输入、输出、流程、确认状态，或所选动作/操作的 Schema。代码、材料和图像按需读取。
- author：创建/更新任务、步骤、规划、流程和组合，导入任务包，获取无模型编写材料、校验候选。基线检查覆盖 expected_hash/revision；不自动覆盖冲突。材料冻结身份并在应用时检查目标仍匹配。
- context：保留现有步骤/规划采集、目标枚举、持久化材料与录制生命周期，绑定 owner/provider/session/recording 身份，保存后 ack。
- execute：试跑、证据确认、整体流程确认、创建/启动、补参、暂停/取消、继续、重试、UNKNOWN 核对；沿用现有租约、版本、命令与组合子运行所有权规则。
- wait：最长 30 秒，返回紧凑状态与下一必要动作；组合等待查询宿主持久状态，不擅自推进流程。
- inspect：按运行、路径、尝试、结果及 JSON Pointer 读取证据或分页日志。循环完整聚合与单实例输出使用现行 run.output 参数区分。
- review：冻结验收要求，生成/读取针对实际执行的核对投影，打开授权桌面验收页。人工决定只由桌面交互记录，工具不能伪造人类身份。

有副作用的外部调用要求稳定 request_id。创建、导入、保存和启动均需处理“成功但响应丢失”的重试；同 ID 同内容返回原结果，不同内容报冲突。未完成回执不能自动重发可能已产生的外部业务动作。现有 command_id 不被替换，回执与其共同工作。

本地定义写入和成功回执在同一控制库 UnitOfWork 中提交。运行控制使用固定 command_id/request_id 及已有运行记录恢复；仍无法判定的回执显示不确定，并提供请求查询，不擅自重发。测试覆盖事务崩溃窗口。编写材料包含当前步骤与任务包 Schema、运行 API/允许内置函数、选中插件贡献、流程语法和变量作用域。一次分支试跑仅证明已访问路径；未访问动作须补输入再试跑或使用明确标为人工确认的已有入口，不能借用另一分支的成功证据。

## 低 token 与数据边界

搜索默认最多 20 项、上限 100；详情按 section 和对象读取。普通工具结果设置明确大小上限，超量给出 next_cursor/引用和 omitted/truncated 信息，不静默截断出貌似完整的证据。日志和大结果按需读取；图片不默认送给 AI；完整结果保留给本地验收。

外部投影复用隐私设置，剔除内部文件绝对路径、环境秘密值、连接令牌和原始请求配置。业务材料属于不可信数据，不提供额外执行授权。只返回所选能力的完整 Schema 和编写贡献；固定运行不调用模型。

## 验收事实与证据

验收要求在运行前与目标/版本绑定并冻结；每项包含 id、中文要求、结果来源和受限比较。首版支持存在、相等、数值比较、计数以及列表 all/any，均读取持久结果，不执行任意脚本。业务中途断言继续使用已有插件动作，不改变流程控制语义。

任务/组合的验收要求可按定义版本复用；review.prepare 生成不可变 review_spec_id，启动时绑定此身份，运行报告永久采用该快照。既有运行没有预先要求时标为未配置，事后补充明确标为事后核对。比较区分 true/1、缺失/null；空列表 all 为 true、any 为 false，正常跳过标为 NOT_APPLICABLE，截断数据不参与完整核对。

结果分为运行状态、自动核对 PASS/FAIL/MISSING/ERROR、人工未验收/通过/不通过。无要求或证据缺失不能宣称自动验收通过。步骤自报布尔值标为业务结果，不伪装成独立观测；插件报告与动作日志说明来源。查看报告不得刷新外部系统或重执行步骤。

证据身份保留 sequence_run_id、组合 node_id、run_id、流程 node_id/execution_path、attempt_id 和 result_id。重复任务、循环多轮、跳过分支、真实 null、历史与当前有效尝试分别呈现；循环尚未完成不展示部分结果为完整聚合。人工决定绑定报告指纹；新尝试或结果失效后显示过期。

首屏显示目标、环境名称、定义版本、运行概况、实际执行路径和核对表；失败轮展开，成功轮可折叠。证据按钮复用已有图像、表格、报告和 JSON 查看器。原始代码、完整日志和输入输出为次级内容。运行与组合详情提供“查看验收”。外部打开返回安全的已认证路由/打开结果；无 GUI 明确说明，不返回虚假入口或令牌。

## 验证与交付

以临时工作空间验证外部编写→草稿→试跑→确认→正式运行→验收的真实 worker 闭环；增加串行组合重复节点、分支、嵌套循环、逐轮输出、缺参、重试、UNKNOWN 与版本冲突覆盖。真实 MCP 客户端通过 stdio 握手、发现与调用；确认桌面打开时仍只有一个 Application。实际浏览器覆盖一次打开正确验收页、证据显示、人工决定和切换隔离。

安全验证覆盖无鉴权、跨工作空间、未知操作、参数错误、令牌/路径泄漏、回执冲突和响应丢失。以同一任务集比较全量目录与按需查询的字节量和调用数，报告实测值而不宣称未经测量的 token 节省比例。

更新受影响模块和契约，测试映射唯一放 tests/module-map.json。运行定向测试、工程检查、差异检查和 Skill 校验；全量、真实远端业务服务及发布验证不在本次默认验证范围。最终由新的 Astra 审核实现及完整目标覆盖，主 Agent 修复阻断项后交付。
