# PDF 文本创建插件

用户于 2026-10-28 确认功能后改选 pypdfium2，并明确移除 ReportLab：独立 PDF 插件，只支持创建并写入文本，支持中文、自动换行和分页，兼容打包成 EXE。

## 范围与接口

新增可选包 taskweave-pdf、pdf extra、pdf 插件与 WRITE 动作 pdf.create；输入仅 path、text，返回 path、page_count、size_bytes；发布成功后的临时文件清理失败通过可选 cleanup_warning 返回，保留已创建结果；发布前清理失败保留原错误码并追加诊断。pdf_root 采用任务参数覆盖环境配置，要求已存在的目录。输出必须在该目录内、扩展名为 .pdf、父目录已存在；目标存在时报错，不覆盖或自动创建目录。动作不自动重试，不记录正文。空文本生成一页空白 PDF。

默认 A4，四边 48pt，12pt 字号、18pt 行距；保留换行及空行，制表符展开成空格，中文与长英文自动换行，满页自动分页。正文为纯文本，尖括号等不作为标记解析。最大 100000 字符，不支持字体缺失的字符或非法控制字符，明确报错并保留已有文件。使用随包静态中文 TrueType 字体，缺字校验，不依赖 Windows 系统字体或在线下载。

## 方案选择与边界

先前考虑 PyMuPDF 覆盖已有 PDF 修改；用户已收窄为仅创建。最终选择 pypdfium2 / PDFium（Apache/BSD 及依赖许可），移除 ReportLab；已有创建能力继续交付，其他 PDF 操作尚未确定动作契约，不据“功能更全”的库选择擅自增加行为。字体采用 Noto Sans SC 的 OFL 字体，固定 Regular 实例，保留许可与可复现生成脚本。只生成文本，不增加 PDF 读取、修改、OCR、页面合并、通用文件写入或界面编辑器。

渲染到同目录临时文件，成功后用不覆盖目标的原子链接发布；不支持该操作的文件系统明确报错。目录范围是配置约束，不作为针对恶意并发替换目录的权限隔离。Windows/macOS 打包收集包、字体、许可、PDFium 原生库与插件 metadata；已有用户插件配置保持原样。

## 验收与限制

测试中文可提取且字体内嵌、文本字面量/空行、长行换行与自动分页、缺字、路径逃逸、已存在目标、取消和失败清理；真实 worker 验证调用与结果。检查 wheel 和 PyInstaller 收集。样例渲染目视检查。当前 macOS 环境不能证明 Windows EXE 实机运行或安装包增量；需在 Windows 构建机补验。按项目规则只执行定向验证，不运行全量、不提交或推送。

## PDFium 接入细节

复用随包静态字体，生成带 SHA256 的字符度量与 glyph ID 映射。按本次文本生成独立 CID/ToUnicode 映射，保留共享字形的不同字符及补充平面字符；普通文本使用 PDFium 原生字体子集保存；当前 PDFium 8076 将子集字体的补充平面 ToUnicode 映射改写为 U+0000，已实际复现，含受支持的补充平面字符时关闭子集保存，保留完整字体及正确文本。PDFium 全部调用在进程内串行执行，显式关闭页、字体、文档；先保存内存再写临时文件，避免 C 回调吞掉文件写入异常。测试依赖 pypdf 仅用于独立提取验证。
