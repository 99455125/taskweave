# 步骤与任务组合控制流及条件并行设计

## 状态与需求边界

2026-10-27 用户修正并授权实施：步骤级和任务组合级的条件分支均增加“允许并行”选项；组合支持条件、遍历、循环并实际执行；应用未正式上线，不承担旧组合、旧历史或旧包格式兼容。本次在现有工作区实现，保护已有修改，不清理用户数据，不执行 Git 写操作。

本段及下一节取代本文后续原串行提案中的冲突条款，并取代任务内并行设计的待审状态。其余条件、循环状态、显式公共输出、实例身份、事务恢复和定向验证要求继续适用。

## 修正后的实施决策

- 条件组提供“允许并行”，默认关闭。关闭时按顺序只执行首个匹配；开启时先基于同一份上游事实判定全部条件并持久化命中集合，所有命中分支可同时执行。零命中只执行默认路径。默认路径不与命中分支并行。
- 并行按执行容量排队，不承诺同一时刻启动；必须有真实动作重叠的验证，界面勾选或多个独立运行不构成步骤级并行验收。
- 每条分支内部顺序、遍历和循环仍按定义执行；嵌套条件可以独立选择并行。汇合等待所有命中路径成功，后续公共任务或步骤不得提前开始。
- 一支失败不重做或撤销其他独立成功分支；其他已运行分支可完成，然后阻塞汇合。补参只阻塞所属路径，暂停/取消作用于整个所属运行；UNKNOWN 必须人工核对，重试定位原分支实例。
- 关闭并行时，首个匹配路径与前后串行步骤复用当前资源会话。并行路径独立资源会话，不继承活跃浏览器页面；需要登录等资源时在路径内显式建立。分支资源释放不能关闭其他路径。执行容量必须有界并避免嵌套并行死锁。
- 公共输出在串行模式取选中分支的映射值；并行模式按稳定分支 ID 返回映射，保留配置顺序，默认路径也有独立身份；不合并同名业务字段。后续步骤可用 JSON Pointer 明确选择。循环输出按轮次聚合。
- 定义使用明确的多分支结构与布尔并行字段，运行时严格校验。无需保留旧格式执行器、旧客户端覆盖策略、旧包读写适配或历史迁移。调整数据库仅采用不清理现有本机数据的方式；不支持格式明确报错，不能静默丢弃数据。
- UI 使用结构化画布、插入/移动入口、条件/循环表单及分支/轮次状态。步骤与组合两处选择、保存重载、调试、运行详情及人工处理均须反映真实执行模式。
- 既有任务步骤、插件 SDK、结果回执和固定执行不调用模型等边界保留。组合包导入导出、自由跳转、break/continue、定时触发及共享活跃资源不在范围。

## 方案比较与推荐

| 方案 | 影响与取舍 | 建议 |
| --- | --- | --- |
| 扩展组合的结构化流程，叶节点仍创建独立子运行 | 保留任务边界和既有执行能力；新增组合游标、轮次实例及映射作用域 | 采用，按用户修正目标实施 |
| 展开所有任务的步骤为一个任务内流程 | 需重新定义重复步骤身份、任务输入、环境、结果及资源边界，改变组合调用任务的现有含义 | 不采用 |
| 引入任意连线图执行器 | 需处理任意回边、不可达节点、汇合和循环识别，超出本次结构化控制需求 | 不采用 |

推荐在组合中增加独立的、带版本的流程契约。复用纯条件求值及适合的纯游标算法；组合定义校验、来源解析、实例持久化、子任务控制由组合模块承担。若抽取共享逻辑，只抽取本功能必需部分，并验证任务内既有行为，不做全工程流程重构。

## 用户可见的编排

保留“任务编排 / 基础配置 / 运行历史”工作区和下方配置面板。画布展示结构化流程，提供添加任务、条件分支、遍历和条件循环；每个顺序容器及控制路径都可插入节点。任务配置继续提供任务引用、环境、任务输入和步骤输入映射。

条件节点展开为多条命名路径及一个默认路径；遍历和循环明确包住其内部任务，显示列表来源、退出条件与轮数上限。选择控制节点时，下方编辑该节点的条件、状态或公共输出；选择任务节点时编辑原有配置。工具栏计数区分任务引用数和控制节点数，执行进度按实际实例计数，循环前不虚构总任务次数。

支持在同一容器调整顺序，以及明确选择目标容器移动节点。节点身份、配置和整个子树随移动保留；移动后重新验证作用域，非法引用给出来源和目标位置。首版以插入、移动菜单完成可审核的结构编辑，不要求自由拖线或拖拽。跨容器移动不会自动改写引用来源。

复制任务引用生成新的组合 node_id，仍引用同一个 task_id；移动保持原 ID。移除含内容的控制块需确认删除范围；破坏引用时标出受影响位置并阻止保存，允许用户先修正草稿。未保存的条件、映射及 JSON 输入在切换选择时保留。保存与执行沿用版本冲突保护和执行前保存链路。

示例：

```text
开始 → 查询待处理清单 → 遍历每份单据
                         └─ 条件：是否需要确认（首个匹配）
                              ├─ 需要：确认单据
                              └─ 默认：记录无需确认
       → 汇总各单据结果 → 结束

循环示例：查询状态 → 若尚未完成，执行处理并再次查询
          每轮结束更新循环状态；满足退出条件后进入后续任务
```

## 定义、条件与执行语义

### 结构与身份

定义分开保存“任务引用配置”和“流程树”。流程树具有顺序、任务调用、条件、遍历与条件循环节点；任务叶节点引用组合 node_id，node_id 再关联 task_id、环境及输入映射。每个配置节点在树中恰好出现一次；同任务多处使用时建立多个引用节点。所有结构节点有稳定 ID，运行路径使用 ID 及轮次构造，不使用名称或界面排序号。

组合流程复用现行控制树版本与纯控制语义，由 sequence_flow 适配组合来源；组合定义修订和任务定义分别管理。多出口条件在新组合契约中显式表示一个条件组，含有序分支和唯一默认出口，每个分支有独立稳定 ID；不编译成多层 if，以免每增加一个出口就消耗一层嵌套深度。组合自身控制嵌套建议最多 8 层，独立于子任务内深度。未知版本、未知字段、重复 ID、未放置引用及非法来源在运行时明确拒绝。

### 条件分支

未允许并行时，各分支按配置顺序判定，只执行第一个匹配路径；允许并行时，先统一判定全部条件，冻结命中集合，执行全部命中路径。零命中执行默认路径，默认路径可以为空。每条路径内部仍按顺序执行。支持全部满足、任一满足、取反、存在、为空、相等、不等、大小比较与包含，沿用现行受限 JSON 条件语义，不执行 Python 或模型判断。

操作数可来自固定 JSON、组合启动输入、已可用的前序任务 JSON 输出、当前遍历项与索引、当前循环状态或上游控制公共输出。环境仍属于各任务配置，组合条件不隐式读取某个子任务的环境。

关闭并行时分支间短路求值，开启并行时判定全部分支；复合条件内部保持短路。类型不适配、普通引用缺失、输出不可用均阻塞并记录原因，不自动转为 false 或默认路径。只有“存在”检查能将确定的值缺失判为不满足，存储和读取异常继续传播。false、0、空字符串、null 与不存在分别处理。

首次判定记录命中分支集合和所依据的值来源；恢复沿已记录路径继续，不因外部现场变化重新选择。全部命中分支执行成功后才推进后续节点。

### 遍历

进入遍历时解析 JSON 数组，冻结数组快照并持久化，再按原顺序逐项执行整个 body。当前项和从 0 开始的索引只对本 body 及其嵌套路径可见；界面同时显示用户可读的第几项。

空数组正常结束，输出为空数组。非数组阻塞，超过 max_items 在启动本遍历任何子任务之前阻塞，不截断。建议默认 1,000 项，可设 1–10,000 项。嵌套遍历的当前项通过所属控制节点区分。恢复使用冻结数组，已成功轮次不重新运行。

### 条件循环

while 在每轮开始前判断，条件不满足时结束，可以零次执行；until 先执行一轮，轮末更新状态，再判断退出条件，条件满足时结束，至少一次执行。

循环状态通过显式初始值和轮末更新映射维护。初始值读取组合输入或已可用的外层来源；更新读取本轮成功输出、当前状态及可用外层来源。各更新表达式读取同一份旧状态，全部求值和校验成功后一次提交，不受字段排列顺序影响。while 的首次判断不能读取尚未运行的 body 输出；需通过初始状态建立首轮判断依据。

每轮成功完成并提交更新后，才允许进入下一轮；轮内失败、补参或 UNKNOWN 均停在该轮。建议默认最多 100 轮，可设 1–10,000 轮。达到上限后，若按该模式已满足正常退出则成功，否则阻塞并标记轮数超限，保留已完成结果。该状态需调整定义后新建运行，不允许原地提高冻结上限。

不提供隐式递增或任意状态脚本：计数可使用轮次索引，业务状态由任务输出或固定值更新。避免持续空控制推进占满线程：分批持久化并检查暂停/取消，建议沿用每批 128 次、总控制访问 1,000,000 次的预算；每个组合运行最多创建 100,000 个子任务实例。超预算明确阻塞；子任务内部原有动作预算独立生效。

## 输入、输出与作用域

任务输入和未绑定步骤输入继续支持原来源，并增加控制上下文与公共输出来源。子任务启动时解析输入，按目标 Schema 校验，持久化解析结果及来源身份；缺失映射值不静默使用默认值。仍只跨任务读取 JSON 输出。

“前序”从列表下标升级为结构上的确定可用关系：同一路径已经完成的任务、可见外层前序任务及已完成控制公共输出可引用；禁止未来任务、兄弟分支、跨轮次隐式取最后一次结果及循环变量逃逸。

条件之后若要使用分支内部结果，必须在条件节点声明公共输出，每条出口显式映射同名值；默认空路径也需明确配置固定值等来源。各路径值可以为 null，但不能用 null 隐藏缺失输出。串行汇合暴露选中出口的公共值；并行汇合按命中分支 ID 暴露各路径公共值。禁止直接引用某个可能未执行的分支任务。

遍历/循环内部引用同 body 前序任务时读取当前轮实例；外部读取结构上可用的 body 任务输出时，按已完成轮次聚合；不增加第二套循环输出命名接口。循环结束后按轮次顺序形成数组，零轮为 []，嵌套聚合保留数组层级；需要简化形状时显式配置逐轮投影，不能自动压平。若 body 内还有条件，先经条件公共输出消除路径差异。

子任务本身的步骤循环输出仍由原 run.output 处理。逐轮投影可用 projection_scope 显式指定 task 或 combination，区分两层循环恰好同名的情形；省略时按组合可见循环推断，界面与运行保持一致。组合轮次与任务内轮次是两个层级，查询与映射必须先确定组合任务实例，再选择该子运行中的步骤输出或投影；原有 item_pointer/loop_node_id 的任务内含义保留。

失败轮次已完成的子任务结果可供历史查询，但整个控制块完成前，后续外层任务不得读取未完成聚合。公共输出缺失或类型错误记录控制错误与来源；不当作成功汇合。

## 持久化、调度和人工处理

组合定义节点与执行实例分离。实例唯一身份为组合运行 ID 加执行路径；路径包含控制节点 ID、分支 ID、各层轮次及任务引用 node_id。同一 node_id 在不同轮创建不同子 run_id；同一路径重试继续使用原子运行，不另建整份任务运行。

组合保存版本化快照、游标、控制实例与实际任务调用实例。控制实例记录判定结果、冻结列表、循环状态、轮次及错误；任务实例记录输入、子运行归属和持久化控制命令。执行记录按实际到达路径逐步建立，不预先展开无限或嵌套循环。跳过路径由分支决策及界面推导展示，不能伪造成功子运行。

每次控制推进以旧游标修订号作并发检查，在同一控制库事务内提交新游标及实例变化。建立待执行任务实例、创建子运行、绑定归属和持久化启动命令在同一控制库事务完成，事务提交后才启动 worker。命令身份纳入组合运行与执行路径，不能只按 node_id 生成。每条路径中的后续任务须等待该路径前一子运行成功、资源释放完成且组合推进记录提交后启动；汇合后的任务须等待全部命中路径完成。

组合级任务实例路径与子任务内部执行路径分别传递。补参、重试、核对须绑定明确的组合实例及对应子运行；允许多个分支分别待处理，旧页面或旧轮次请求明确拒绝。历史成功实例只供查看；原子任务入口继续不能独立改变组合子运行生命周期。

| 情况 | 建议行为 |
| --- | --- |
| 容量不足 | 当前任务实例等待资源，不推进下一实例，不标业务失败 |
| 缺少人工输入 | WAITING_INPUT；补参只续启本轮原子运行 |
| 子任务失败 | 该分支阻塞，独立已启动路径继续；最终 BLOCKED；明确选失败实例及步骤/执行路径重试，保留成功任务 |
| UNKNOWN / 不确定副作用 | BLOCKED；沿用人工核对及显式继续，不自动重发业务动作 |
| 条件、映射或控制输出错误 | BLOCKED；展示组合路径和错误来源，不自动跳过或切默认路径 |
| 暂停 | 先持久化组合停止意图；正在运行的子任务按原机制暂停；控制边界也可暂停，无子任务时可继续 |
| 取消 | 阻止后续控制推进与子任务创建，对当前子运行执行原取消流程，保留历史 |
| 应用重启 | 先恢复普通运行，再按组合游标、实例、回执和有效结果接管；已完成控制决定及轮次不重算 |

子运行成功与组合消费成功之间发生中断时，恢复先核对子运行，再以游标修订号提交消费，不重复创建或再次执行。组合归属保护、任务/环境引用检查与历史删除须覆盖所有实际实例及冻结定义；删除保留持久化清理意图，逐项释放子运行与结果，不因只找到一个 node_id 而遗漏其他轮次。

启动前静态校验整个流程及全部引用任务，包含未命中分支中的任务确认状态、环境、插件与可校验输入；运行时只为实际到达节点创建子运行。每次创建子运行前继续比对冻结任务/环境/插件指纹，漂移阻塞。快照用于还原配置及验证身份，不承诺直接执行已变化的旧任务代码。

修复瞬时基础设施问题后，可在同一冻结实例明确继续；缺失必要业务输出、错误条件、非法输入映射或超限不能通过修改正在执行的快照来修复，应修改定义并新建组合运行。从头重跑始终创建新组合运行，不撤销原运行中的已成功外部操作。

## 变更影响

以下为本次实现的验收场景，实际覆盖和结果记录于实施计划；本表自身不作为通过证据。

| 场景 | 必须观察的结果 |
| --- | --- |
| 编辑与往返 | 添加、移动、保存重载控制结构；重复引用同任务身份独立；非法跨路径引用阻止保存；草稿切换不丢失 |
| 多出口条件 | 关闭并行只执行首个，开启并行执行全部命中；零命中仅走默认；条件集合冻结；错误不启动部分路径 |

| while / until | while 零轮、until 至少一轮；轮末同时更新状态；最后允许轮退出成功与仍未退出超限分别成立 |

| 停止与预算 | 无动作控制段和两子任务交接处可暂停/取消；不再启动后续任务；嵌套控制/子任务总预算阻止无界增长 |
