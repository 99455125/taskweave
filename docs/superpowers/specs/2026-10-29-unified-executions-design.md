# 统一执行与组合调试

用户已确认：任务和任务组合统一在“执行”启动、管理；组合子执行仅在组合详情内查看；组合页只编排和调试，调试不创建正式执行记录。本次直接按已确认范围实施，沿用当前工作区并保护已有修改。

## 设计

- 任务、任务组合维护可执行定义。“执行”列表显示独立正式任务运行和正式组合运行，隐藏组合拥有的子运行及所有调试运行。筛选、搜索和状态覆盖两类对象。
- 新建执行选择组合后填写组合及节点启动输入，启动完成留在“执行”并选择对应组合记录。
- 组合详情展示冻结定义、输入、节点状态及子执行结果/日志；暂停、取消、继续、补参、重试和核对通过现有组合管理接口执行，明确节点执行路径，避免重复任务或并行分支操作错对象。
- 删除组合记录同时删除该次组合及子运行和结果，不删除定义；运行中先停止。子执行不提供独立删除/重跑入口。
- 组合编辑页仅保留编排、基础配置、调试。组合调试使用独立 `TRIAL` 模式并冻结在组合快照中，全部子运行使用完整任务流程调试，支持未确认步骤/流程但保留结构、插件、输入和运行时校验。调试记录留在组合调试页，不混入正式执行。
- 不改变本机已有记录和数据，不引入数据库迁移或历史改写。现有组合快照缺省为正式模式，新增调试快照明确记录 `mode=TRIAL`。
- 用户追加确认：浏览器步骤结束后自动保存本步骤实际操作/读取页面的 PNG 和图片 views，正式执行与调试均覆盖。图片 view 可直接引用本次文件输出，不往业务 data 中塞入元数据，保持输出 Schema 与绑定不变；截图失败记录明确警告，保留业务执行结果。只对后续执行生效，不补造历史现场。

## 取舍

沿用组合调度和任务执行引擎，抽出共用的组合详情组件供正式执行与调试复用。仅隐藏删除按钮无法满足统一管理；重写调度会扩大范围，两者均不采用。

## 验收

定向组件事件测试验证统一启动、列表与过滤、选择刷新和删除/重试路由；真实临时工作空间 worker 验证组合调试的全部子运行均为 TRIAL、完整循环推进、结果映射及正式运行不受影响；工程检查核对分层、源码和文档映射。不运行全量测试，不操作真实业务数据。
