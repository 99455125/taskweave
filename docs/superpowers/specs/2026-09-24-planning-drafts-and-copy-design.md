# 规划草稿生成与复制规划设计

## 目标

用户能根据不完整的页面证据先生成并导入一份有用的任务草稿，再逐步补充上下文、生成代码和调试。局部缺少控件、业务取值或插件能力时，不让整份规划失败。用户还能复制已有规划，只重新采集发生变化的页面。

## 生成边界

规划生成区分三种情况，所有 AI 生成步骤始终为 `DRAFT`：

1. **代码可生成**：生成完整、通过静态校验的 `step_content`。尚待运行验证的事实写在该步 `step_notes` 的“待调试：”小节，不声称已成功执行。
2. **目标明确但代码暂不可生成**：仍生成步骤名称、`step_description`、`step_notes`、已知输入/输出结构和插件要求；`step_content` 为空。`step_notes` 的“待补充：”小节具体说明缺少的控件证据、业务值或能力。不得生成假选择器、跳过操作、固定成功或抛异常的占位代码。
3. **整个规划无法成立**：仅当最终目标互相矛盾，或连主要业务阶段和步骤边界都无法确定时，返回 `PLAN_INFORMATION_MISSING`。局部材料缺失、某个步骤暂时不可执行以及尚未采集最终按钮，均不属于整份规划失败。

能确定是运行时业务输入、但没有取值的字段，声明为带中文说明的必填变量，不猜默认值。不能确定字段含义或类型时只在相应步骤说明，不编造 schema。前序步骤输出若尚不能可靠确定结构，后续步骤不建立虚假的 JSON Pointer 绑定；在关联步骤标注待补充的输出契约。候选预览按步骤显示“待编写”或“待调试”，并集中显示待补充事项。

## AI 回复与导入

规划 AI 回复沿用顶层 `format`、`origin`、`task`、`steps` 的任务包结构，并允许规划生成专用的顶层 `plan_context_refs`：按步骤 `key` 列出所引用的规划上下文 `context_id`。解析器先验证这些引用均属于本次生成请求保存的规划快照，再剥离该字段，使用现有 `taskweave-task-2` 校验和导入任务配置。该附加字段只用于规划生成入口，不写入可携带的任务导出 JSON，也不让普通 `task.import` 接受它。生成记录另外冻结原始上下文快照；发送给 AI 的内容仍遵循“发送 AI 时脱敏”设置，两份材料不能混用。

对于 `ai_generated` 的 `DRAFT` 步骤，导入校验允许空 `step_content`，但仍校验任务包结构、变量 schema、已声明能力及版本、可判定的绑定关系；非空代码仍执行完整静态校验。`task_export` 原有状态和校验规则保持不变。空代码步骤不能确认或执行；用户补齐代码并通过现有校验后才可调试、确认。正式执行仍要求相关步骤满足已有确认规则。

导入时将 `plan_context_refs` 指定的冻结上下文复制到相应步骤上下文表，生成新的 `context_id`，保留提供者、名称、操作说明、采集内容、采集参数、预览数据及相对顺序。步骤上下文来源枚举增加 `planning_import`，界面显示“规划导入”；不能复用原规划的会话 ID、浏览器实例或实时资源。导入过程整体成功或整体回滚，避免出现只有任务没有上下文的半成品。未被步骤引用的规划上下文继续只留在原规划中。复制后的步骤上下文可独立重采集、编辑和删除，不回写原规划。

生成响应中的上下文引用只允许来自本次请求快照；若用户在 AI 生成后修改或删除规划上下文，导入仍使用该次生成时冻结的材料，不从当前页面状态拼凑。引用缺失或越界时给出明确的步骤和上下文错误，不默默跳过。

## 复制规划

规划列表的每条记录增加“复制”操作。复制前先等待当前规划的待保存内容落库。新规划默认命名为“原名称 副本”，自动打开，用户可直接修改名称。

副本保留规划描述、全局操作说明、环境选择、插件选择，以及每条上下文的提供者、名称、操作说明、采集内容、采集参数、预览数据、是否生成预览和排列顺序。新规划及所有上下文获得新 ID；上下文的采集时间作为历史证据保留。副本不复制 AI 生成请求/回复/导入记录，不复制或连接原规划的活动插件实例和会话。环境若已被删除，副本的环境为空；插件是否可用仍按当前注册表判断。原规划和副本可独立编辑、重新采集和删除。

复制为单次数据库事务；失败时不留下不完整副本。采集内容和预览当前均为可序列化 JSON，因此无需复制规划目录中的运行文件。

## 提示词与界面

只改规划场景的提示词：明确“先生成可编辑任务草稿”“局部缺证据要落到对应步骤，不要阻断整份任务”“代码只能完整且真实，否则为空”；保留现有通用执行契约对非空代码的约束。网页 Chat 与 API 使用同一业务规则，网页仍保留现有 JSON 转义要求。

候选预览显示任务级待补充数量、每步状态、描述、说明、代码及关联上下文名称；导入后空代码步骤打开在步骤编写页，方便补充材料。只显示有操作价值的缺项，不为每个未见按钮生成重复提醒。

## 验证

仅运行规划、任务包与上下文导入相关的定向测试及项目静态检查；不运行全量测试。覆盖：局部缺证据仍可导入、空代码不能确认/执行、非空代码仍受静态校验、上下文引用校验与复制顺序、生成后原规划变化、复制规划数据独立、复制不带活动会话或生成历史。
