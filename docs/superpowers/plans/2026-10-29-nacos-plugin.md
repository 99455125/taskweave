# Nacos 插件实施计划

目标：在 TaskWeave 中读取、选择、发布和增量更新 Nacos 配置，通过步骤组合跨环境同步。

- 实现独立插件，沿用现行 SDK、环境配置和密钥引用；不涉及服务发现或账号管理。
- JSON 局部更新读取目标、递归合并对象；数组及标量按指定值替换，不自动删除未指定字段。并发更新需由服务端原子校验保护。
- 确认版本接口后实现读取、列表、发布及安全增量更新，清楚报告失败和副作用未知状态。
- 为合并、协议、认证、并发冲突和插件注册编写针对性测试；同步插件知识、包注册和测试映射，运行定向验证。
- 真实 Nacos 验收取决于可用的测试服务和凭据；不连接或改动生产数据。

## 2026-10-29 用户补充：字段与多命名空间

- 范围：按嵌套字段增删改、列表元素增删、逗号分隔字符串元素增删；支持 JSON 与 YAML，读取来源选定字段，向多个指定命名空间应用相同变更。
- 操作按完整路径定位，保留未涉及字段；重复匹配、缺失字段等有歧义情况拒绝写入。YAML 含重复键或锚点时拒绝增量修改，避免改变其他路径；序列化保留注释与引号，带 CAS 发布。
- 命名空间发现走 Nacos 2.x 只读接口。目标选择交互及逐目标失败处理需结合 TaskWeave 启动输入和运行状态确认，不能假定普通插件已有动态界面。
- 当前已完成纯字段操作、YAML 文档操作、单目标 CAS 动作、命名空间列表与来源字段选择的定向测试；批量流程、交互、文档、打包和最终验证仍需完成。

- 已提供 `nacos.namespaces`、`nacos.select_fields`、`nacos.update_fields`、`nacos.update_many` 和 `nacos.update_batch`；批量按命名空间和配置依次执行，开始/完成均记日志，失败停止并保留已成功目标信息。
- 已修复 YAML 布尔歧义、删除注释和带引号列表项；字段更新读取并保留目标类型与可用元数据，拒绝加密配置。CAS 不能阻止 Nacos 2.4.3 并发删除后重新创建。
