# 工程规范

- 使用 `src/taskweave` 包布局，运行入口不在导入时启动服务或改数据库。
- 核心保持与具体插件、UI 和存储解耦；避免为尚未确定的功能添加空抽象类或新框架；旧代码不作为必须复用的约束。
- 任务模型、插件协议和持久化格式以 REQ-002 详细设计为基线；变更时同步契约与对应检查。
- 插件依赖在插件中声明，缺少插件时将来应明确报告，不隐式调用 AI 或其他工具替代。
- 运行记录与任务定义分离，副作用步骤的重复执行、恢复和失败语义必须在功能需求中明确。
- 配置和运行产物保存在本地，示例不包含真实账号、数据库、登录态或业务文件。
- 自动化步骤可复用给测试，但不依赖 UI 按钮；公共操作与测试断言职责明确。
- 改动运行行为时增加能发现真实回归的测试；纯文档/目录调整以结构和引用验证为主。
- 改数据库先制定迁移与回滚方案，不复用旧启动时自动生成迁移脚本的方式。
