# 后续产品范围

本页保留尚未实现或尚未验收的产品知识，不自动启动任务。当前进行中事项仅见 [状态](status.md)。规划编写已有实现；它不等于运行时AI自主规划。旧编号先后顺序不再是今天必须按序执行的指令。

## 分享与离线分发

已有taskweave-task-2 JSON任务导入导出和复制，契约见 [任务分享](reference/task-sharing.md)。待设计/验收的是版本化zip manifest与资源清单、导出预览、明确ID冲突策略、显式更新覆盖与环境/角色映射、可选离线wheel、Python/OS依赖兼容及敏感内容剔除。

允许模型的环境与受限执行环境之间，完整的草稿/依赖与用户筛选脱敏feedback包协议仍需明确；现有JSON任务包和网页Chat不能代替完整离线反馈交接验收。

模板导入与安装插件分开，只启用受信任插件；不自动安装未知来源，也不实现在线市场。默认分享不含运行库、登录态与产物；现有源码/默认值/上下文可包含敏感值，因此“自动无凭据分享”仍是验收目标。显式覆盖不得覆盖活跃运行配置，历史保持。

验收必须在独立home往返绑定/上下文；缺插件或版本冲突列明解决项；损坏资源/zip越界路径拒绝且不覆盖原任务；分享包检查凭据及绝对路径；匹配Windows/Python的离线依赖实际验证。便携目标不允许安装，不能把开发机离线wheel验证当该目标验收。基础线性分享无需等待控制流；后者新增格式须自行升级兼容。

## 条件、循环与子流程

尚未实现，当前仍为线性任务。拟采用结构化节点，不允许任意连线形成隐式循环：

- 条件使用受限比较和明确默认分支，不执行任意代码表达式。真/假结果确定，缺失输入不静默走默认分支；未选中分支显示未选中而非失败。
- 循环显式集合或条件、迭代变量、最大次数和超时；初版顺序，集合在运行开始冻结。零次/多次/上限及失败可追溯，失败默认停止，重试不重复已确认副作用。
- 子任务按ID引用，输入输出显式映射，拒绝不存在引用、循环引用与递归。参数隔离、输出可回传。
- 以节点路径、迭代序号、子运行ID定位。单步、暂停、退出恢复继续同一迭代，UNKNOWN不自动重试；能进入子流程查看。

实施须同时覆盖持久化升级、旧线性任务兼容、导入导出及基础运行回归。不能仅加模型字段即宣称交付。

## 流程图编辑

依赖稳定控制流模型，先用交互原型验证组件，不预选库。拖拽已验证步骤、能力及控制流节点；参数面板展示输入、前序输出、分支/循环/子任务配置。布局坐标单独保存，图形和列表编辑使用同一执行模型，worker仍执行实际浏览器动作。

保存前定位断开节点、非法端口/引用/环路、缺少分支出口和未验证内容。验收图形保存重开语义/布局一致、列表往返不丢参数或稳定ID、活跃运行不可覆盖、运行高亮及迭代/子流程定位、结果日志跳转；新增定义分享和旧格式迁移也需验证。

## 候选而非承诺

多实例并发已有1–8池容量，后续系统级资源配额/排队仍需独立定义。定时调度与无人值守、运行时模型解析/提取/判断、AI动态选择动作或调整执行路线、在线插件市场与远程协作均未纳入当前固定执行交付。AI辅助编写/调试固化已有，不以运行时接入模型为前提。Excel仍不是核心或当前基础交付的必需插件。

### 与现有架构的衔接

- 每个插件独立包及可选依赖，使用现有entry point、CapabilitySpec与ResourceProvider；核心不引入SSH、容器或数据库客户端依赖，不按具体插件写页面分支。
- 连接/进程对象留在所属worker资源中；步骤间只通过JSON数据、输入绑定和声明产物交接，插件不直接互相调用。文件读取可复用已有`file.read`，上传/远程执行接口名待SSH设计确定。
- 所有动作声明输入/输出schema、效果、超时与重试安全性。任意本地/远程命令按可能写入处理，不因输出像查询就标READ；提交、发布、上传及SQL写入不自动重试。专用只读观察动作独立声明。
- SSH配置包含显式目标、端口、用户及认证引用，核验主机身份；密钥/密码不放入任务源码、导出包或AI上下文。连接关闭、取消、超时与远端命令是否仍在运行分别处理，不能把关闭连接当作撤销远端副作用。
- 结果保留实际退出码、结构化数据、日志与文件引用；长输出有界展示，完整产物按需查看。需要后台任务时，必须先明确远端任务身份、查询/停止和结束确认，不默认为无限跟随日志。
- 各插件按需要贡献环境/服务/仓库/报告上下文及声明式预览，兼容已有标题、操作说明、分组和默认关闭的发送预览；采集证据与执行业务分开。
- 当前线性步骤已可组合这些能力。条件、循环、子流程、无人值守调度仍按各自规划处理，不能通过插件暗中扩展核心执行模型。

优先设计SSH/SFTP、本地进程、HTTP三个通用能力包，再按实际流程补Git、容器和报告。每包验收包含临时或用户明确选择的目标、实际成功/失败、取消/超时、重复执行边界、产物往返及旧插件兼容；仅列出方法或使用模拟服务不能标为真实目标验收。

### 宝塔与 WordPress 建站插件

2026-10-01 用户明确将宝塔Linux面板和WP-CLI纳入后续插件范围，目前仅登记规划，尚未新增插件代码。两者为独立可选能力包：宝塔负责服务器站点环境，WP-CLI负责WordPress应用，流程由任务步骤组合，不互相直调。

- 宝塔优先采用面板API，配置显式面板地址、API密钥引用、TLS校验与访问白名单。官方[API文档](https://www.bt.cn/data/api-doc.pdf)可作为起点，但接口与响应须按实际面板版本验证，不把旧文档中的全部操作视为当前已兼容。首轮覆盖站点查询/创建、域名与PHP配置、数据库创建及结果核对；证书、备份和日志在目标版本验证后纳入。创建网站、数据库等部分成功须分别报告，不因HTTP请求成功就判整体成功。
- WP-CLI按[官方命令参考](https://developer.wordpress.org/cli/commands/)封装结构化动作，显式指定站点路径、PHP/WP-CLI版本、执行用户与目标；支持本地执行和官方[远程SSH模式](https://make.wordpress.org/cli/handbook/references/config/)，具体运输资源在插件实施设计中确定。使用可执行文件及参数列表，不拼接用户输入为shell命令；不默认启用任意PHP执行。首轮覆盖安装检测/初始化、配置、主题/插件、内容/媒体、用户管理、数据库导出/导入和域名替换。页面构建器或第三方插件专有布局须另核对其API/CLI支持，不能把安装主题当成完成页面设计。
- 建站模板组合：宝塔准备站点/数据库 → WP-CLI初始化并配置应用 → Playwright检查页面 → 保存截图、日志及备份。主机、站点路径和产物通过显式输入输出绑定，凭据经本地密钥引用交接，不混入普通结果、日志或任务包。查询按需执行，不新增常驻面板探活或UI高频轮询。
- 验收使用隔离临时站点：实际创建/初始化、再次执行不重复建站、目标路径/版本错误、认证失败、超时后的部分成功或未知副作用、备份恢复及浏览器访问核对。已有站点不得隐式覆盖；更新、导入、域名替换与删除不自动重试，报告真实结果。实现时沿用插件API v1，新增可选依赖不进入核心默认环境，不改变旧任务包和旧插件行为。
