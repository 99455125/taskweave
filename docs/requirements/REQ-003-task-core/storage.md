# 存储与结果设计

## 现有代码核对

当前 legacy 来自 smart_client_easy：Step 没有版本字段，BaseModel 只有创建/更新时间。step_content 保存步骤描述，step_sql 保存 AI 生成且执行验证成功的 SQL；后续有 step_sql 时直接执行。不能把旧 step_content 与可执行 SQL 当成同一个字段，新的通用内容契约需明确“目标描述”和“可执行内容”。

- `legacy/smart_excel/db_server/config/db_config.py`：总库 `task.db_server`。
- `legacy/smart_excel/tools/db/db_tool.py`：任务 SQL 使用 `task_{task_id}.db_server`。
- Task、Step、TaskTable、TaskFile 使用总库 ORM；TaskTable 的表结构与少量预览 JSON 也在总库。
- 当前模型主要记录当前状态，不含完整的每次运行/每次尝试历史表。新执行记录是本次补充，不能宣称旧版已有。

## 新设计：总库记录管理信息，任务库默认保存返回的业务数据

```text
data/
  taskweave.db                    # 任务、步骤配置、运行/尝试、状态、错误摘要、结果引用
  tasks/
    <task_id>/
      data.db                     # 需要持久化业务结果或工作表时才创建
      artifacts/<run_id>/         # 截图、下载、报告、详细日志等文件，按需生成
```

以上为拟议路径，新项目不自动改写旧数据文件。

总库保存任务列表、当前步骤描述及执行内容、校验状态、插件配置引用、任务运行和步骤执行记录、结果位置/类型/简短说明。完整业务输出、业务中间表不塞进总库。

任务库保存该任务需要持久化的结构化输出、上下文数据和工作表。一个任务一个文件；用 run_id、step_id、attempt_id 区分同任务不同运行/尝试，避免结果覆盖或串用。无需持久化业务数据的任务不创建任务库。所有返回的数据默认落库；后续步骤按稳定 step_id 引用同一 run 的有效成功 attempt，从任务库读取，不依赖内存。

文件型结果放到任务自己的文件目录，总库只保留索引。截图不是数据库表；浏览器 Page/Context 是进程资源，不能当执行结果保存到 DB。

## Playwright 结果按需

| 场景 | 步骤结果 | 存储 |
|---|---|---|
| 点击、打开页面、登录、提交后只需确认成功 | 成功/失败、耗时、简短错误 | 总库执行记录即可 |
| 创建单据供后续步骤使用 | 单号、地址、提取字段 | 默认写任务库，后续步骤从库中读取 |
| 截图、下载、trace | 文件引用 | 任务文件目录 |
| 抓取多条业务数据 | 结构化结果集 | 默认写任务库 |

执行结果契约区分状态与可选数据：状态必须有，data/artifacts 可以为空。无业务数据不强制创建业务表；有返回数据则默认落库。业务成功由插件断言或前置/后置检查确定，函数没抛异常不一定等于业务成功。

## 分库隔离与一致性

分库适合本地单人使用，避免不同任务的数据表同名和数据清理相互影响；但它不等于任意 Python 插件的安全沙箱。插件通过任务作用域的数据访问接口取得当前任务库，不默认拿到总库或其他任务连接。

总库与任务库通过稳定 run/step/attempt ID 关联。若两个独立连接分别提交，不假设跨文件原子事务：先在总库登记 RUNNING，任务侧用 attempt_id 写入结果及完成标记，再在总库登记结果引用/状态。异常退出后按标记核对；业务外部状态仍不确定时标为 UNKNOWN，不自动重做提交。

不需要持久化输出的任务按执行状态恢复；清理结果、删除任务和备份要同时考虑总库索引和任务目录，提供显式操作。总库短事务写入；任务业务数据不占用总库长事务。

SQLite 适合设备本地存储；不同数据库文件可用于划分数据，但每个文件仍有自己的写并发限制。参考 [SQLite 适用场景](https://www.sqlite.org/whentouse.html)。

## 步骤保存

不做步骤版本、修订树或版本选择界面。AI 与手动生成同一种当前内容；修改后验证状态失效，试跑成功再保存为可执行步骤。活跃运行期间不覆盖其配置。保留运行状态、错误和验证摘要属于执行记录，不是步骤版本体系。插件版本与存储格式版本仍用于兼容检查，与步骤版本不同。

## 结果保存的插件扩展

插件提供结果结构、自定义表声明、转换、解析与预览；核心统一提供数据库保存、事务、文件落位、索引和清理。返回的数据默认持久化，跨步骤读取数据库。见 [结果处理协议](../REQ-004-plugin-contract/result-handling.md)。

## 本地变量（2026-09-18 调整）

按用户选择，环境与任务参数允许直接保存本地普通值（包括密钥值），运行私有 inputs_json 保存实际值，摘要/服务日志仍脱敏。不写入操作系统环境。env: 系统变量引用保持可选兼容，不强制使用。步骤变量通过 inputs["name"] 引用，自动合并优先级为环境 < 任务默认/运行输入 < 显式步骤绑定/试跑输入；任务默认值参与正式绑定解析，additionalProperties=false 的步骤仅接收声明变量。无 DDL 变更。
