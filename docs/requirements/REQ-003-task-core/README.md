# REQ-003 · 任务与步骤

状态：可运行核心已交付，待用户验收。依赖：REQ-002。

## 负责什么

- 任务和步骤的当前配置、参数与前后步骤数据传递；不建步骤版本表。
- AI 生成、手动编写、手动修改及 AI 修正，共用内容校验、试跑、业务验证和保存流程。
- 统一编写服务组合插件提示词、上下文、工具与诊断贡献；固定步骤执行不依赖模型。
- 单步、连续、执行到指定步骤、暂停、失败恢复、重复执行防护和执行记录。
- 总库管理配置与执行记录；为插件提供当前任务数据库/文件目录、结果索引和清理入口。
- 返回的业务数据默认保存到任务库，同任务用 run/step/attempt ID 区分结果；插件定义结构和解析，核心管理实际读写。

## 验收标准

- [ ] 输入步骤目标和插件能力后可生成符合项目内容契约的 step content，支持用户编辑与 AI 修订。
- [ ] 插件提供的提示词、参数约束和示例进入对应生成上下文；未选择的能力不可静默调用。
- [ ] 试跑失败保留草稿与反馈；业务验证成功后可保存已验证内容，修改内容需重新验证。
- [ ] 固化后的任务执行不调用模型；草稿/反馈可在允许使用 AI 的环境与执行环境之间传递。
- [ ] 同一任务的结果以 run_id 区分；历史记录保留，活跃运行时阻止覆盖配置。
- [ ] 缺少引用或前置条件时动作未启动，返回明确原因。
- [ ] 步骤二失败后步骤三不执行；重试保留两次尝试记录。
- [ ] 前置步骤输出改变后，下游旧输出不可继续作为有效结果。
- [ ] 重复执行命令只启动一次尝试；并发请求不创建两个活跃 worker。
- [ ] worker 在执行中退出后尝试显示 UNKNOWN，不自动重做副作用动作。
- [ ] 重启后能打开历史运行；会话恢复先检查插件版本与业务条件。
- [ ] 迁移失败保留旧库或可从备份恢复；读取旧版本有明确提示。
- [ ] 账号和 Token 不出现在数据库输入摘要及普通日志中。
- [ ] 步骤只保存当前内容和验证状态，不创建步骤版本表。
- [ ] 总库管理配置和执行记录；两个任务可有同名业务表且互不影响，同任务结果按 run_id 区分。
- [ ] 无业务数据的浏览器动作只写总库状态，不创建任务库；返回数据时核心自动创建任务库并保存，后续步骤从库中读取。
- [ ] 在结果已写入、总库未确认时模拟崩溃，通过 attempt_id 核对，不重复执行副作用。
