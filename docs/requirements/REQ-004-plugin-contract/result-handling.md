# 插件结果处理与存储契约

| 核心统一负责 | 插件提供 |
|---|---|
| 默认保存步骤输出到当前任务库 | 业务结果与 schema |
| 连接、建表迁移、事务及任务隔离 | 自定义表、列、索引与兼容迁移声明 |
| 写入 JSON、表记录和文件引用 | 将结果转换为存储描述 |
| 按 run/step/attempt 读取有效结果 | 将存储记录解析为业务值 |
| 索引、清理与通用展示入口 | 自定义结果预览 |

插件不提供数据库保存实现，结果处理器不接收连接或 TaskStore。核心校验存储描述并统一执行；普通 JSON 无需插件处理器。详细接口见 [总体插件协议](../REQ-002-task-plugin-design/plugin-contract.md)。

步骤 5 引用步骤 1 时，核心从当前任务库读取同一 run 中步骤 1 的有效成功 attempt，按需调用插件解析，再传给步骤 5。结果必须提交后才能供下游使用；缺失或解析失败明确报错，不用其他运行的值补齐。前置步骤重跑后下游旧输出失效。

Playwright 点击可仅返回状态；返回单号或抓取数据则默认保存；截图和下载文件放任务目录，数据库保存引用。浏览器 Page/Context 属于运行资源，不能序列化为结果。

保存失败不得自动重做外部业务。核心利用 receipt 核对恢复；缺少插件时保留原始结果及索引，报告解析能力不可用。REQ-005 调用统一结果服务展示数据，服务按需使用插件解析/预览。

### 2026-09-19 结果展示声明 v1

`ctx.result(data=..., outputs=..., views=...)` 增加可选 `views`，默认空列表，旧步骤及插件无需修改。业务内容只保存在 `data`；展示声明为 `{title, renderer, pointer}`，使用 JSON Pointer 引用字段。框架提供 `core.json`、`core.table`、`core.report`、`core.image`；插件可选实现 `result_views()`，以命名空间 ID 注册声明式展示器（type 为 json/table/report/image）。插件不直接访问 UI。

展示声明与业务结果在同一任务 DB 事务中保存，内部保留名 `__views` 存储 `{version:1, items:[...]}`，不创建业务结果引用，不改变前序输出绑定。无 DDL 或模板格式变更；旧结果没有声明时回退 JSON。图片文件使用已保存 outputs 名称引用，禁止直接传任意文件路径。报告支持 passed/message、带标题的多个 tables，以及 query_info。界面渲染已保存内容，不重新执行动作。

API 和 Chat 编写上下文包含所选插件展示器与格式说明；用户在目标中要求保存表格或截图，AI 生成 views。使用插件并不会自动创建展示项。

执行列表“详情”文字固定；详情中成功步骤展示勾。成功步骤旁的查看图标打开对应有效成功尝试的结果窗口，多项展示使用标题页签，保留原始数据；历史详情按具体尝试查看。TiDB 插件已支持连接、只读查询及表格和核对报告展示。


### 截图展示引用兼容与输出保存（2026-09-19）

图片展示支持本次尝试保存的文件名称、结果 ID、`{output: 名称}`、`{capture: 引用}`及 Base64。旧截图 staging UUID 只在本次尝试存在唯一图片时兼容匹配；多个图片不会猜测，也不允许任意文件路径。若只有 staging UUID 而没有保存文件，不能恢复历史图片，需修订并重新试跑。

`ctx.output` 创建请求而非立即保存；必须把请求加入 `ctx.result(outputs=[request])`。Playwright 图片输出请求传完整截图返回对象，不是 staged_file 字符串。API 和 Chat 插件提示词已补充完整示例；静态检查拒绝丢弃返回值的独立 ctx.output 调用。
