# REQ-004 设计边界

先采用显式入口注册和单插件单启用版本。插件是受信任本地代码，worker 不是安全沙箱。插件依赖由自身声明，浏览器 SDK 不进入核心依赖。动作同时可供自动化测试复用。

依赖：REQ-003。实现前阅读 [总设计](../REQ-002-task-plugin-design/design.md) 和依赖需求的已交付契约；本文是实施输入，不代表功能已完成。具体字段、消息与接口以 REQ-002 为基线，实施变更记录兼容影响。

## 关键交付

- 插件 manifest、插件/核心版本兼容与动作注册。
- 动作输入输出描述、预检查、执行结果、结构化错误。
- 日志、产物、取消信号和会话资源上下文。
- 可安装的最小自定义插件、示例和开发说明。

## 非目标

不做插件市场、热更新、任意目录扫描执行或自动安装模板附带代码。

插件基础执行接口在 REQ-002 定义并由 REQ-003 接入，本需求不得通过重新设计执行模型实现插件化；必要的契约调整需记录兼容影响。步骤从草稿、业务试跑到已保存内容的验收以 README 为准。

## 插件对 AI 编写能力的扩展

插件除提供执行能力，还实现统一的 `StepAuthoringContribution` 编写上下文接口（名称暂定），向 REQ-003 提供：

- 能力/动作说明、版本、可调用 API 与输入输出 schema。
- 面向 step content 的提示词片段、调用约束、前后置条件及成功判断方式。
- 合法内容示例、常见错误、调试建议与可脱敏收集的上下文说明。
- 可选静态内容校验器和试跑结果解释器，返回统一的诊断信息。

项目公共规则负责 step content 格式、入口、上下文和结果规范；插件只能补充能力约束，不能覆盖公共规范。REQ-003 组合多个已选插件的贡献；不兼容或冲突时明确报错，不按加载顺序悄悄覆盖。

插件不各自维护一套模型调用和步骤保存流程。上下文版本与插件版本绑定，步骤保存依赖清单；生成结果必须通过项目校验和对应插件预检查。提示词引导不能代替实际校验。

## Playwright：插件架构的首个真实验证

浏览器资源由固定 worker 拥有；角色使用独立 BrowserContext。通用能力与业务页面定位器分开，插件不依赖 UI 按钮。模拟业务可在本机验收，真实内网页面、账号和 Windows 环境未提供前不得宣称真实业务验收通过。

依赖：REQ-003、REQ-004；界面验收依赖 REQ-005。实现前阅读 [总设计](../REQ-002-task-plugin-design/design.md) 和依赖需求的已交付契约；本文是实施输入，不代表功能已完成。具体字段、消息与接口以 REQ-002 为基线，实施变更记录兼容影响。

## 关键交付

- Playwright worker 内会话、页面和角色资源管理。
- 通用导航/截图与自定义业务动作复用接口。
- 可见浏览器单步停留、人工接管和继续检查。
- 可本地运行的模拟业务页面与完整业务插件示例。
- 业务查询检查、重复提交防护、失败截图和恢复策略。

## 非目标

不绕过验证码、不承诺进程退出后无缝还原活页面、不预设所有业务页面布局。

## Playwright 编写上下文

通过 REQ-004 的贡献接口提供浏览器 API/封装动作说明、角色会话获取方式、定位器与等待规则、人工接管约束、业务成功断言和 step content 示例。补充可脱敏的页面结构与调试信息供用户选择；不默认上传整个页面或登录态。REQ-003 负责 AI 生成、修订、试跑与保存，Playwright 只提供能力和对应知识。

## 结果职责确认

REQ-003 管执行状态、任务隔离存储、结果索引和生命周期；REQ-004 插件定义业务结果结构、自定义表及解析和预览。状态必须有，业务数据可为空；返回的数据默认由核心落入任务库，核心统一负责事务、索引和清理。详见 [结果处理契约](result-handling.md)。

详细字段与接口以 [REQ-002 已交付契约](../REQ-002-task-plugin-design/README.md) 为准；本目录补充本需求的实现范围与验收。

## 已落地选择

公开 SDK 为 taskweave.plugins.sdk，插件使用标准 Python distribution entry points。配置持久化至本地 plugins.json；默认入口保留 demo/text 本地测试适配器，浏览器和第三方包明确启用。启动加载错误可见且隔离，配置变更则严格校验并原子写入。能力描述从 methods 派生，不在 manifest 重复维护。

Playwright 浏览器在 worker 固定事件循环里运行，role 资源独立。完整 Chromium 通道同时用于可见/无头模式，运行时不下载；开发机依赖版本按平台约束并由 uv.lock 锁定。人工接管通过窗口动作与通用暂停配合，继续步骤负责查询业务状态。

新增通用失败产物钩子、当前 worker 上下文观察及可机器检查的 AuthoringContribution.constraints。截图记录不产生成功 receipt。任务库升级到 schema v2 管理自定义表版本，核心执行兼容加列/索引，提前备份且事务失败回滚；任意插件 SQL 和破坏性迁移不开放。

Playwright 0.2.0 增量：selector 兼容 CSS 字符串并支持结构化 role/label/placeholder/frame；新增输入值读取/断言和 URL/title 断言；时间标识可见快照、失败诊断与插件提示词，兼容策略及限制见插件 README。核心仍通过通用动作与 ContextItem 交互，不引入 Playwright 依赖。

2026-09-18：新增独立 captcha 插件，使用随包 ddddocr 1.6.1/ONNX Runtime 1.20.1 本地 CPU OCR，模型和识别在 worker 单线程执行，无网络或 API Key；识别普通图片文字，返回候选文字并要求业务验证。Playwright 新增通用 page_element_image 采集元素 PNG Base64，核心不导入 OCR 或按插件硬编码。插件对 API/网页渠道提供提示词；验证码图片、输出长度和模型初始化失败有明确错误，不自动刷新或无限重试。Windows 10 x64 免安装包与真实业务验证码准确率待实机验收。
