# REQ-004 · 插件架构与 Playwright

状态：代码已交付，待用户验收。依赖：REQ-002 契约与 REQ-003 应用服务。

## 负责什么

- 插件注册、动作描述、依赖兼容、启停及统一执行接口。
- AI 扩展涵盖提示词、上下文、可调用工具、内容校验、业务断言、调试反馈和资源管理。
- 结果处理扩展：业务输出及自定义表结构、结果转换、解析与预览；REQ-003 核心统一完成持久化。
- 实现独立 Playwright 插件，覆盖会话、多角色、单步停留、人工接管、截图与业务示例。
- 用 Playwright 和最小示例插件验证架构通用性，核心不硬编码具体浏览器逻辑。

## 验收标准

- [x] 安装示例插件后可列出动作并由任务调用；卸载或禁用后预检查明确失败。
- [x] 重复插件 ID、重复动作和不兼容版本拒绝启用。
- [x] 输入和输出不符合声明时报告对应字段，不标记成功。
- [x] 第三方示例插件不导入核心内部模块，可按开发说明独立构建。
- [x] 两个插件可通过统一贡献接口帮助生成 step content，无需修改核心生成流程。
- [x] 插件约束不能覆盖项目内容契约，冲突和不兼容版本有明确提示。
- [x] 插件执行与内容校验接入 REQ-003 的统一试跑/固化流程，不另建 AI 编写服务。
- [x] 启用 Playwright 后，由统一注册入口发现动作、提示词、约束和示例；核心中没有 Playwright 专用判断或直接 SDK 导入。
- [x] AI 生成和纯手动编写的 step content 均能调用插件，在 REQ-003 中试跑、反馈、验证和保存。
- [x] 禁用插件后核心及无浏览器任务仍可使用，引用浏览器能力的步骤在预检查时明确报错。
- [x] 多角色隔离、单步保留浏览器、人工接管、失败截图与不确定提交处理通过测试。
- [x] 最小示例插件复用相同接口，验证机制不限于 Playwright，避免为浏览器特设整套接口。
- [x] Playwright 验证提示词、页面上下文、AI 工具调用、内容校验、业务断言、诊断反馈和会话资源扩展，统一由步骤服务调度。
- [x] 工具观察和有副作用的试跑分开；固定任务执行不再次调用模型。
- [x] 步骤输出可以只有成功/失败状态，无数据时不强制建表；结构化结果和文件分别使用任务存储接口与产物目录。
- [x] 插件可定义结果结构、自定义表及解析；核心默认保存返回结果并管理事务、索引和生命周期。
- [x] 结果保存失败不会触发自动重复业务提交；不同任务结果处理互不串库。
