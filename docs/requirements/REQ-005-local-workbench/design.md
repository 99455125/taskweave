# REQ-005 设计边界

采用列表式步骤编辑与三栏执行视图。UI 按 Windows / macOS 跨平台独立客户端实现：NiceGUI native mode + pywebview。共用界面、应用服务、任务模型和插件契约；平台适配只处理窗口后端、资源路径、进程生命周期和打包。两个平台的启动与后台进程分别实际验证。UI 只调用应用用例，通过事件刷新，不把浏览器对象塞进线程池或页面会话。

依赖：REQ-003、REQ-004。实现前阅读 [总设计](../REQ-002-task-plugin-design/design.md) 和依赖需求的已交付契约；本文是实施输入，不代表功能已完成。具体类/字段/消息格式在实施时补齐并记录兼容影响。

## 关键交付

- 本地任务列表、新建、复制、编辑、排序和任务参数。
- 插件动作选择与 schema 驱动基础表单。
- 运行选择、单步/到此步/连续/暂停/结束操作。
- 步骤详情、错误、输出、日志、截图和运行历史。
- 本地环境/角色配置、运行前检查和空状态提示。

## 非目标

本需求交付基础界面；拖拽流程图由 REQ-009 实现并共用任务模型。多人账号权限和云端工作台不在本期范围。

## 客户端交付

Windows 双击 TaskWeave.exe、macOS 打开 TaskWeave.app，均打开独立窗口，内部回环服务不要求用户操作浏览器。业务 Chromium 由 Playwright 单独启动。详见 [Windows 交付方案](../REQ-007-v1-release/windows-package.md)。

目标机禁止安装任何程序或运行库。桌面窗口后端须优先验证随包 WebView2 在目标机直接运行；若需要被禁止的系统安装或权限修改则方案不通过，调整为可随包分发的后端，不把依赖补装交给用户。

## 跨平台边界

- 首期支持 Windows 10 x64 与 macOS；macOS Intel / Apple Silicon 分别构建并验证，最低系统版本由依赖兼容测试确定，不先承诺全部版本。Linux 不纳入本期验收。
- Windows 窗口采用 WebView2 候选后端；macOS 采用系统 WebKit，通过 pywebview 平台依赖接入。两者展示同一份 NiceGUI 界面，不开发两套业务逻辑。
- Playwright 业务 Chromium 与桌面窗口分开管理；各平台携带匹配的浏览器文件，不能共用 Windows 和 macOS 二进制。
- 数据使用现有统一 home 解析与 TASKWEAVE_HOME 覆盖机制，程序资源和用户数据分离，不随平台引入第二套任务存储。
- REQ-005 验证源码运行和窗口生命周期；REQ-007 分平台构建分发包、验证依赖完整性与退出清理。Windows 目标机离线、禁止安装、仅允许运行 EXE 的要求继续有效。

后端依据：[pywebview 平台依赖](https://pywebview.flowrl.com/guide/installation.html)。

## 原型评审调整 · 2026-09-17

一级导航：任务、插件、环境与角色、设置。选中任务后，顶部显示该任务名称及二级菜单：步骤编写、执行、运行历史；这些页面始终限定到当前任务，提供返回任务列表入口。

步骤设置新增“与上一步的执行间隔（秒）”，非负数，默认 0。按本次运行中上一步成功时间计算最早启动时间，例如成功后 30 秒执行。首步骤无前序，不等待；上一步失败或结果待核对时不启动下一步。单步与继续操作遵守间隔，已达到最早启动时间则立即执行；单独试跑不依赖前一步。等待期间显示剩余时间，可暂停或结束。

用户已确认原型；步骤契约新增 delay_after_previous_seconds（整数，默认 0，上限 86400），总库 v3 保存该字段、任务排序、定义快照和等待截止时间。核心调度按前序有效成功尝试的 finished_at 计算截止时间，不在 UI 中 sleep。

## 实施结构

界面位于 src/taskweave/desktop，以可选 gui extra 引入依赖。Application 在回环服务 startup 中创建，shutdown 中关闭；main guard 与 freeze_support 防止 spawn 重复启动协调器。UI 服务调用放后台线程，工作台按钮在请求期间阻止重复提交，核心命令继续使用稳定 receipt。结果和日志按真实状态更新，未配置模型不影响手写和固定执行。

任务与每次运行分离，v3 definition_json 为执行证据快照，不提供步骤版本功能。模型连接在本地 model.json 持久化 API Key 和其他连接配置，环境变量引用作为备选；页面与 Socket.IO 使用本次启动 cookie 授权，拒绝非回环 Host 和跨来源访问。

### 试跑变量与紧凑列表 · 2026-09-18

试跑反馈显示环境变量、任务本次输入、步骤输入及依赖三个可折叠区域；环境区域只读，任务输入与未绑定步骤输入均可修改；绑定步骤输入展示只读来源与示例值。切换环境重新加载实际值，不沿用旧环境重复试跑；不同环境的活跃浏览器不能复用，使用既有资源结束确认后创建新会话。同环境重试继续保留页面，并使用当前任务输入。

步骤编写列表用名称与序号配绿色勾/灰色圆标记，四个工具按钮固定在顶部，步骤单独纵向滚动。执行行顶部显示环境，内部步骤单独横向滚动，详情/结束/暂停固定在右侧；省去未开始、就绪和重复状态文字，成功绿色，未执行灰色，失败红色。历史详情继续保存完整执行信息。


### 输入阶段与结果字段选择 · 2026-09-18

新建正式执行仅选环境，任务必填输入在首次开始时收集，步骤必填输入在该步骤动作前收集。运行使用现有 PAUSED 状态及 request_json.waiting_input 标识等待输入，不启动失败尝试；输入提交后按原 ALL/NEXT/UNTIL 目标继续同一个运行及会话。每步临时输入单独保存到 request_json.step_inputs，不修改定义；绑定结果始终重新从本次任务 DB 解析。等待表单不存储已绑定的执行结果副本。重新从头执行清空每步临时输入并保留本次任务输入。

依赖表单按来源显示相关控件，固定值第一、前序结果第二。前序结果读取最近同任务同环境成功结果生成受限深度/数量的字段列表和示例，JSON Pointer 转义字段名，允许手写路径；保存绑定自动声明输入及已观测类型。独立单步试跑可读取最近成功前序结果；正式执行与流程试跑不能使用其他运行结果代替当前结果。

成功按钮为绿底白字，勾在名称后；草稿/未执行灰底灰字，失败为红色。四个固定工具按钮与列表滚动边界保持不变。


### 执行重跑与参数补录（2026-09-18）

- 删除任务入口位于任务列表，确认后删除；任务配置只负责编辑和保存。
- 步骤验证不要求与执行环境匹配，修改环境不使步骤重新变成草稿。环境提供变量，不作为验证通过的条件；已创建执行仍保留配置快照一致性检查。
- 点击已成功步骤，可选择开始步骤，执行到点击的步骤。清理开始步骤及其后续输出、尝试和步骤本次输入，前面的成功结果保留，其他执行不受影响。中间重跑复用当前运行资源；从头重跑清理全部结果并重新建立资源。
- 每次执行的详情在该执行行下方展开或收起，步骤横向滚动，操作按钮固定在右侧。
- 缺少任务或步骤必录参数时，在对应执行点暂停并弹窗补录。调试反馈继续展示环境、任务和步骤三类变量，必录字段标注“必录”。取消补录保持暂停，可再点击补录按钮继续。
- `run.restart` 新增可选 `start_step_id`，旧调用仍从头执行，无数据库迁移。选择中间起点时，其之前的步骤必须已成功，避免悄悄执行未选择的前置步骤。


### 执行卡片清理与一致的补录界面（2026-09-18）

每次执行卡片右上角提供 × 删除入口，确认后仅清理该次执行、日志和结果，其他执行与任务保留。正在运行的步骤须结束后删除，保留资源的完成运行删除时释放资源。增加 `run.delete` 接口，无 DDL 变更。删除执行列表外的独立详情容器。仅在选中的执行内部创建详情；收起或切换执行时删除原容器，不保留隐藏面板。

执行试跑、从首步开始、结束测试统一放在反馈顶部的一列；状态成功绿、失败红、普通灰，不在每次尝试下重复结束按钮。全局普通按钮采用中性色，移除蓝色底色。

独立试跑弹窗采用自身选中的环境和对应变量；开始后同步反馈页的环境及本次输入，后续试跑使用这次选择，避免重新使用页面旧环境。任务/步骤分组默认仅展开有必录输入的部分。执行补录弹窗复用同一分组界面，固定显示本次执行环境、任务变量与当前步骤变量/依赖，依赖结果读取本次运行的 DB；默认展开当前需要补录的分组，其他分组只读。


### 默认环境和首步补录优化（2026-09-18）

环境列表可设为默认，默认项左上角显示“默认”；默认环境 ID 存入本地 workbench.json，重启保留并作为首次环境选择。任务列表删除按钮放在最右侧。普通按钮白底蓝字；优先/选中操作浅青底、青绿边框，不使用蓝色底。执行删除 × 红色，与其他操作留出间距。

执行详情在所属执行内部展开，头部提供“收起详情”，执行行的详情/收起开关仍保留。补录弹窗放在稳定页面容器下，每个 InputRequested 生成唯一请求 ID，同一请求刷新不重建、不重复弹出，稍后填写可手动重开。任务参数和首步可编辑参数在首次补录中共同输入，提交时原子保存任务输入及首步 step_inputs；run.inputs 新增可选 step_inputs，旧调用保持兼容，无 DDL 变更。后续步骤到达时仍按需补录。

### 2026-09-19 结果展示声明 v1

`ctx.result(data=..., outputs=..., views=...)` 增加可选 `views`，默认空列表，旧步骤及插件无需修改。业务内容只保存在 `data`；展示声明为 `{title, renderer, pointer}`，使用 JSON Pointer 引用字段。框架提供 `core.json`、`core.table`、`core.report`、`core.image`；插件可选实现 `result_views()`，以命名空间 ID 注册声明式展示器（type 为 json/table/report/image）。插件不直接访问 UI。

展示声明与业务结果在同一任务 DB 事务中保存，内部保留名 `__views` 存储 `{version:1, items:[...]}`，不创建业务结果引用，不改变前序输出绑定。无 DDL 或模板格式变更；旧结果没有声明时回退 JSON。图片文件使用已保存 outputs 名称引用，禁止直接传任意文件路径。报告支持 passed/message、带标题的多个 tables，以及 query_info。界面渲染已保存内容，不重新执行动作。

API 和 Chat 编写上下文包含所选插件展示器与格式说明；用户在目标中要求保存表格或截图，AI 生成 views。使用插件并不会自动创建展示项。

执行列表“详情”文字固定；详情中成功步骤展示勾。成功步骤旁的查看图标打开对应有效成功尝试的结果窗口，多项展示使用标题页签，保留原始数据；历史详情按具体尝试查看。TiDB 连接/查询插件随后在本轮补充实现，见下节。

### 2026-09-19 TiDB 与任务配置分享

- 可选 database extra 提供 `plugins/tidb`，使用 PyMySQL/MySQL 协议，连接配置读取环境及任务变量，提供连接测试、表结构采集、参数化只读查询和 tidb.table/tidb.verification 展示器。数据库连接每次关闭；API/Chat 共用插件格式，Chat 不假装可以访问数据库。
- 任务列表提供导出 JSON、复制 JSON、下载 JSON，以及粘贴导入为新任务。`taskweave-task-1` 包含任务名称、说明、参数默认值、按序步骤内容/参数/插件要求/绑定；前序依赖通过可移植步骤 key 重映射。环境、历史、文件和执行结果不导出。导入执行静态检查和插件校验，不运行步骤，全部标记 MANUAL/VALIDATED；缺失插件或无效配置拒绝导入，失败不留下半个任务。只支持当前线性步骤配置。
- 环境列表支持确认后删除，保留历史业务结果，历史执行保存 deleted_environment_name 并解除外键；保留资源、运行或暂停中的环境禁止删除。默认环境删除后清除默认设置。环境不提供导入导出。
