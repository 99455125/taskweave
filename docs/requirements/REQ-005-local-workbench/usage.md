# REQ-005 使用指南

## 启动独立客户端

```bash
uv sync --locked --extra gui --extra browser --extra sample
uv run --extra gui --extra browser --extra sample taskweave workbench
```

只使用核心示例动作，可省略 browser 与 sample；GUI 是可选依赖，不进入默认核心安装。Playwright 浏览器文件需按 REQ-004 在开发机准备；界面不会自动联网下载浏览器。程序、插件和匹配 Chromium 的免安装冻结包由 REQ-007 交付，当前不是可复制到 Windows 的 EXE 包。

独立窗口模式默认启用。Windows 使用 WebView2 候选后端，macOS 使用系统 WebKit；平台实际验证证据见 validation.md。服务默认仅监听 127.0.0.1，选择空闲端口，启动凭据同时保护页面和 Socket.IO；一个工作空间由 OS 锁保证只有一个 Application 协调器。

指定开发数据目录：

```bash
uv run --extra gui --extra browser --extra sample taskweave --home .runtime/workbench workbench
```

开发和自动化检查可以显式启动浏览器检查模式，使用终端打印的带凭据 URL；它不会自行打开浏览器，不是客户端默认交付方式：

```bash
uv run --extra gui --extra browser --extra sample taskweave --home .runtime/workbench workbench --browser --port 8788
```

## 操作顺序

1. 新建任务，填写名称、说明与参数定义，不需要编辑任务 JSON。任务列表支持复制与排序；复制重建步骤 ID 和依赖，不复制确认记录或执行历史。
2. 打开任务，顶部二级导航为步骤编写、执行、运行历史。任务配置始终针对当前任务。
3. 添加步骤，直接手写内容；或者在动作表单中选择插件动作、填写参数并插入调用，再继续编辑。允许的能力会随动作插入更新。
4. 输入与依赖中定义步骤参数，以及固定值、任务参数、环境配置或前序结果的绑定。字段路径使用 JSON Pointer，空路径表示整个输出。前序结果由核心从任务 DB 查询。
5. 步骤设置中配置上一步成功后的等待秒数，默认 0，范围 0–86400 整数；首步骤忽略间隔。超时只计算步骤执行，不含间隔。
6. 调试时选择环境并填写有效输入。单独调试不自动执行前序步骤，对结果依赖可手动填入样例值。成功后回到内容页确认验证并保存，也可直接手动确认验证成功并保存；任何修改使旧确认失效。
7. 正式执行前检查所选环境和步骤确认状态；在执行列表新建执行，点击步骤选择继续到此步或从头执行到此步。运行期间可以暂停、继续、结束，查看输入、输出、错误、文件和尝试记录。
8. 若外部操作结果未知，先在业务系统查询，再输入实际查询证据并核对；重试需明确选中步骤。普通点击不能保证任意外部系统只提交一次。

等待间隔显示剩余时间，可暂停或结束；从前序成功时间计算，暂停、关闭客户端后重开不会重新等待完整间隔。结束运行后不能继续，该操作用于释放资源并允许编辑。上一步失败或待核对时不启动下一步。

执行及调试记录保留定义快照；不是步骤版本系统。修改当前配置不覆盖历史快照。升级总库到 v4 前自动创建对应原始版本的备份；旧记录没有快照时只能展示已有执行证据，不伪造历史内容。

## AI 编写

设置页可直接输入 API Key，与完整 Chat Completions 接口地址、模型名一起保存到本地 model.json，重启自动读取。留空保留同地址已保存密钥，环境变量引用仍可选。接口须 HTTPS，本机模型可使用回环 HTTP。首次也可用 TASKWEAVE_MODEL_URL、TASKWEAVE_MODEL_NAME、TASKWEAVE_MODEL_API_KEY 配置。

AI 生成/修订先保存当前草稿，结合插件贡献、目标和已采集上下文生成建议，不携带历史对话。界面展示差异，用户采纳后可手动调整，随后调试确认或手动确认验证成功；正式执行不调用模型。测试连接按钮明确实际调用一次模型。

插件上下文可选择独立观察，或当前任务仍存活的 PAUSED / FAILED / SUCCEEDED 会话；插件能力决定可采集内容。预览后用于下一次生成，不因此自动执行任务。

没有模型仍可完成手写、动作表单、调试和固定任务执行。

## 环境与插件

环境页保存名称和通用 Key/Value 变量；插件配置说明在插件管理查看，浏览器参数可在任务参数中设置。现有自定义配置保留，保存环境会使使用该环境的步骤需要重新验证。活跃运行阻止覆盖对应环境和任务。

插件页显示安装发现、启停、版本、动作和加载错误；活跃运行期间不能更改插件配置。结果面板调用核心 result.read，经插件解析和预览；文件可以打开或打开所在位置，截图以内联方式查看，不公开整个任务目录。

## 验证入口

```bash
uv run --extra gui --extra browser --extra sample python -m unittest discover -s tests -v
uv run --extra gui --extra browser --extra sample python scripts/check_project.py
uv run --extra gui --extra browser --extra sample python scripts/check_req002.py
```

UI 集成用实际 NiceGUI 服务、真实 Chromium 和本机模型 fixture；仅缺少 GUI/browser Python 依赖时跳过。真实外部模型和 Windows / Apple Silicon 仍需单独记录验证。

模型 HTTPS 使用随依赖安装的 certifi CA 证书包，不依赖 uv Python 默认 CA 文件。企业代理的自定义证书可通过 SSL_CERT_FILE 或 SSL_CERT_DIR 补充；不关闭 TLS 验证。

## 服务实时日志

顶部“服务日志”按钮打开独立原生窗口（浏览器调试模式打开新标签）。通过现有 NiceGUI Socket.IO 实时更新，支持级别筛选、暂停、清空显示、打开日志目录。关闭窗口不结束任务；服务退出会回收日志窗口。日志保存在 home/logs/server.log，超过 5MB 保留一个轮转文件，界面保留最近 2000 行。记录服务操作、AI 请求阶段和后台 logging 异常，按用户要求记录 AI 请求对话与回复正文，密钥和 Authorization 头脱敏；任务 worker 的业务日志仍在任务执行/调试页面。

DeepSeek Chat Completions 按服务域名应用非思考模式与输出额度，避免编写协议需要承接 reasoning_content；兼容服务仍使用标准 Chat Completions。解析兼容 tool_calls=null 与 JSON 围栏，拒绝空输出、截断输出和缺失步骤内容。测试连接还检查 async run 语法；连接成功不等同于业务调试成功。

## API Key 本地保存 · 2026-09-17

按用户确认，API Key 与 URL、模型名称一起保存在 home/model.json，启动自动读取。留空保存保留同地址已保存密钥，切换地址不沿用旧密钥。环境变量仍为备选。该约定取代此前会话内保存、不落盘的说明；日志仍脱敏。

步骤“使用的插件”选择整个插件，自动包含其全部当前动作，不逐一配置动作权限；明细在插件管理页展开查看。底层仍保存明确动作列表，插件新增动作后需重新保存并调试验证，不隐式改变已固化步骤权限。AI 生成使用未授权动作时自动纠正一次，仍失败报告具体动作。

## 浏览器保留与分段执行

同一任务、同一环境的连续步骤调试复用调试浏览器；调试成功后不自动关闭。调试反馈里的“结束调试”显式释放。正式运行独立于调试会话：可以先“到此步”执行到第三步，选第五步再次“到此步”，成功步骤不重复执行。暂停和全部成功后保持浏览器，使用“结束运行并关闭浏览器”释放。关闭成功运行的浏览器不会把历史成功状态改成取消。退出程序会释放资源。

当前单执行器不会同时保留多个浏览器运行会话；启动另一个任务、不同环境或新的正式运行时切换到独立会话。应继续选择原运行以推进，避免新建运行。程序重启不恢复已关闭的网页会话，只保留数据库执行证据。步骤输出继续由任务 DB 传递，单独调试可从同任务同环境最近成功的前序结果填充依赖；从首步开始与正式执行使用本次运行的任务 DB 结果。

调试日志旁的“AI 根据调试日志修复”将当前步骤、原目标、失败信息与最近尝试脱敏日志交给当前模型，显示差异建议，由用户采纳后再调试。日志限制 50 条及 16KB，不把服务全部日志发送给模型。

AI 对话请求和回复正文同时出现在实时日志及本地 server.log；包括调试修复提供的错误/日志、插件提示词与模型修正重试。不会记录 Authorization 请求头或隐藏思考内容。

日志修复先填写可选补充说明；同一步骤本轮调试的 AI 对话只保存在服务内存，修复时全部携带，从内容页新开调试或退出程序后清空。超过编写上下文大小会报错，不静默删掉对话。采纳立即保存草稿并保持所在标签；后续调试读取最新内容，通过调试确认或手动确认验证后可正式运行。

## 执行列表与环境配置 · 2026-09-18

执行页默认展示本任务正式执行列表，每次执行为横向一排。右上角“新建执行”选择环境，只创建记录；任务必填输入在首次开始执行时填写，步骤必填输入在执行到该步骤时填写，不立即执行。点击某次执行的步骤后选择：从前面未执行的步骤继续到此步、清理本次结果从头执行到此步、取消。成功步骤继续时跳过；从头执行清理本次的输出、截图/文件、自定义表行、尝试和日志，其他执行不受影响。暂停/结束入口在执行行，详情保留输入、输出和日志。运行中的步骤应先暂停/结束再重启。

环境菜单仅为“环境”，环境编辑为名称及 Key/Value 变量。角色可以作为普通变量；凭据通过 Value=env:系统变量名提供，不单列凭据界面。既有配置保留；插件参数说明在插件管理页查看。

Playwright 支持任务参数 playwright_headless（布尔，默认 false）、playwright_timeout_ms（毫秒）、playwright_role（默认 operator）、playwright_executable_path（可选）。在任务配置的参数 schema 中设置类型和默认值；本次任务输入可覆盖默认值。插件读取 task_parameters，优先于环境同名变量，既有 browser 配置仍兼容。调试使用上方任务本次输入及步骤本次输入，不修改任务或步骤定义的默认配置。

服务日志长行自动换行，避免大模型对话需要横向滚动。AI 内容差异使用程序 difflib 比较生成，模型仅返回步骤内容。

## 手动确认验证成功

步骤页“手动确认验证成功并保存”不要求成功调试。保存当前内容后，执行语法/动作权限与插件 lint，标记为当前环境下已验证；记录 validation_source=MANUAL，不伪造调试成功。调试确认记录为 TRIAL，任何定义修改仍使验证失效。用户手动确认不代表程序执行过此步骤。总库从 v3 自动备份迁移至 v4，新增验证来源字段，任务库保持 v2。

结束执行/结束调试前弹框确认，根据插件资源声明提示将关闭或释放的已创建资源。无插件资源时只释放执行器，取消不操作。结果与历史保留。

反馈页再次执行调试直接沿用上一调试环境和输入，并使用最新草稿。修复→采纳→再调试→再修复会累计历次修复对话；普通生成/修订始终不携带历史。

添加新步骤默认继承按任务顺序的上一个（末尾）步骤的全部插件，可继续手动增减；首步骤默认不选插件。

观察会话只显示本次启动中仍保留的真实资源；应用重启后为空，历史执行记录仍保留。成功调试后验证保存不关闭浏览器，可在下一步骤选中此会话采集。

失败调试可直接修订当前步骤并在反馈页重试，无需结束浏览器；未知结果会提示检查页面并确认重试，旧失败证据保留。正式执行和正在运行的步骤仍禁止修改。

“执行调试”旁的“从首步开始”关闭现有调试资源后，从首步调试到当前步骤，选择环境与任务参数，使用真实步骤绑定和前序数据库结果；不要求步骤先验证，失败即停止，保留原历史。

## Playwright 上下文与修复 · 0.2.0

采集展示真实可见控件及状态、推荐定位器和时间；输入框值使用 page_input_value / page_assert_value，不使用文字读取。支持 CSS 或角色、标签、placeholder 定位，支持明确 frame。

“AI 根据调试日志修复”自动刷新当前保留页面；反馈含具体失败动作、定位器、匹配状态、耗时、失败时快照及截图引用。发送失败时证据与当前快照，二者时间分别标明。浏览器已丢失则告知无法刷新，不导航、不打开新浏览器。切换任务/环境清空手动采集的上下文缓存。普通生成仍不带历史，修复仍累计本次调试对话。

Playwright 提示词优化与插件一同启用，要求继续当前页面并验证真实业务结果。0.2.0 新增能力需重新保存“使用的插件”选择后授权；旧正式执行使用原版本快照，需新建执行。

AI 对话在服务内存中保留，应用重启后清空。每次生成都可选择 `0`（不带历史）、最近 `1–10` 轮或 `-1`（不限制轮数），并可勾选“去除历史中的重复静态字段”。勾选后只去除旧轮次中已由本轮再次提供的目标、步骤源码、输入输出定义和变量清单；旧轮次的反馈、日志、采集上下文与 AI 回复保持完整。能力目录和当前页面上下文不压缩。

结束执行/调试按钮仅在本次启动中仍保留执行会话或执行器占用时显示，历史成功不等于会话仍开放。人工核对需选择业务结果，说明选填，无说明也可保存。

## 网页 AI 编写

在“AI 生成 / 修订”或“AI 修复”中选择 Chat 网页方式，设置历史轮次及是否去除重复静态字段，再复制对话内容到网页 AI。将整段回复粘贴后点“解析并预览”；程序解析 `step_content`，校验步骤，并显示 AI 解释和程序生成的代码差异。只有在预览窗口点“采纳到编辑器”才保存草稿。随后可在当前反馈页继续调试，不需配置 API Key。本机工具无法在网页调用；未采纳的导出不追加历史，采纳修订回合仅放内存，重启清空。

推荐网页 AI 严格返回 `{"step_content":"完整 async def run(ctx, inputs) 代码","explanation":"中文说明"}`。可直接粘贴整段网页回复；即使 JSON 前后有网页额外文字，程序也会提取其中的有效步骤对象。采纳前会检查 Python 语法、单一 `async def run` 结构、已选插件能力和插件 lint；校验不通过不写入草稿。

## 任务与环境变量引用

本地环境配置不修改系统变量，普通值可直接保存。任务配置定义 loginurl、orgcode、orgsecret 等参数及默认值；调试或新建执行选择对应环境。步骤代码直接使用 inputs["loginurl"] / inputs["orgcode"] / inputs["orgsecret"]，自动读取配置，无需逐一绑定；需要前序结果或重命名时仍可使用输入绑定。显式步骤输入/绑定优先，其次任务参数，其次环境。AI API 与网页提示均提供可用变量名和引用规则，不提供默认密钥值。

AI 编写请求的本地上限固定为 128 KiB。程序严格采用用户选择的历史轮数，不因超限自动压缩能力目录、页面上下文或日志，也不自行减少轮数；超限时提示改选更少轮次，`0` 表示完全不带历史。

调试反馈中可展开「环境变量」「任务变量」「步骤变量与依赖」。环境只读；任务和未绑定的步骤变量支持本次输入，不改写默认配置；绑定的步骤变量展示来源与最近成功结果示例。切换环境后读取新环境；存在旧环境浏览器时，首次调试需确认结束旧资源，无法跨环境保留页面。步骤列表顶部 +/↑/↓/− 固定，列表支持鼠标滚动；执行行步骤支持横向滚动，详情和结束位于右侧。


### 依赖设置与本次输入（2026-09-18）

绑定来源顺序为固定值、前序结果、任务参数、环境配置。选择前序结果后隐藏固定值，选择前序步骤，可从最近同环境成功结果下拉选择字段（例如 `/image_base64`）；字段选择可自动填入输入名称，保存时自动补充输入参数及已知类型。普通结果容器默认为 `data`；没有结果示例时允许手工输入字段路径。历史结果只用于字段选择及独立单步调试；正式执行和从首步调试仍取本次运行结果。

调试反馈的「执行调试」「从首步开始」使用上方环境和输入，不再次选择环境；从首步开始仍确认重置当前调试资源。任务输入与步骤输入均可在本次运行修改。必填参数若未配置，运行在相应步骤之前暂停，填写后点击「提交输入并继续」，不会把缺少输入记成失败尝试，浏览器继续保留。环境或任务已有有效值、固定值及前序结果已绑定的输入不重复要求填写。


### 执行重跑与参数补录（2026-09-18）

- 删除任务入口位于任务列表，确认后删除；任务配置只负责编辑和保存。
- 步骤验证不要求与执行环境匹配，修改环境不使步骤重新变成草稿。环境提供变量，不作为验证通过的条件；已创建执行仍保留配置快照一致性检查。

### 2026-09-19 结果展示声明 v1

`ctx.result(data=..., outputs=..., views=...)` 增加可选 `views`，默认空列表，旧步骤及插件无需修改。业务内容只保存在 `data`；展示声明为 `{title, renderer, pointer}`，使用 JSON Pointer 引用字段。框架提供 `core.json`、`core.table`、`core.report`、`core.image`；插件可选实现 `result_views()`，以命名空间 ID 注册声明式展示器（type 为 json/table/report/image）。插件不直接访问 UI。

展示声明与业务结果在同一任务 DB 事务中保存，内部保留名 `__views` 存储 `{version:1, items:[...]}`，不创建业务结果引用，不改变前序输出绑定。无 DDL 或模板格式变更；旧结果没有声明时回退 JSON。图片文件使用已保存 outputs 名称引用，禁止直接传任意文件路径。报告支持 passed/message、带标题的多个 tables，以及 query_info。界面渲染已保存内容，不重新执行动作。

API 和 Chat 编写上下文包含所选插件展示器与格式说明；用户在目标中要求保存表格或截图，AI 生成 views。使用插件并不会自动创建展示项。

执行列表“详情”文字固定；详情中成功步骤展示勾。成功步骤旁的查看图标打开对应有效成功尝试的结果窗口，多项展示使用标题页签，保留原始数据；历史详情按具体尝试查看。TiDB 插件已支持连接、只读查询及表格和核对报告展示。
