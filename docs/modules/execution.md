# 执行与结果

## 职责与主链路

RunUseCases接受创建、启动、补参、重跑、控制、核对和结果查询；CoordinatorPool分配实例，Coordinator协调运行，WorkerTransport管理进程/消息，worker加载插件并实际执行步骤。执行状态与有效结果以持久化事实为准。

SequenceUseCases保存结构化任务组合，SequenceDriver复用纯流程游标，按执行路径创建和推进普通正式子运行；条件可以选择全部命中分支并行。创建子运行与记录节点归属共用控制库事务；节点启动与补参等控制命令保留稳定ID，重启后按子运行事实接管。组合拥有的子运行只能通过组合入口改变生命周期。

## 当前行为

- 正式执行读取确认后的定义与版本快照。调试区可新建现场或选择同环境的已有运行现场，支持跨任务复用；试跑记录及输出仍归本次任务。共享物理现场的执行、采集和结束操作串行，过期现场与变化的环境明确拒绝；实例池并发设置范围1–8。
- 输入由环境、任务值、步骤默认/显式覆盖及绑定解析；具体优先级见[步骤契约](../contracts/steps.md)。单步调试显式false、0和空字符串不等于未填写。
- 缺少必录输入时暂停并记录waiting_input身份；查看运行只显示手动补录入口。RunInputs/InputSubmission保留原始草稿、校验、防重及续启原命令；接受补录后离页仍完成后台续启。
- 从中间重跑要求前序成功，撤销起点及之后的有效输出；从头重跑重新建立资源。旧尝试保留为历史，不再冒作当前输出。
- command_id、命令指纹、锁、租约与回执共同防重复/冲突操作。副作用不确定进入UNKNOWN/人工核对，决策为completed或not_completed，不自动重发业务动作。
- 结束/清理判断同时核对活跃资源、租约与未保存录制，不能用历史成功状态推断可安全结束。

结构化任务流程在定义快照中冻结流程树。运行器按顺序推进动作、`if`分支、`while`/`until`条件循环和`foreach`列表遍历；每次动作、分支选择及循环轮次都有执行路径和持久化实例。列表遍历在进入时冻结列表，逐项执行后按原顺序聚合输出。步骤的前置间隔按前一次成功动作的完成时间计算。流程游标与控制实例在同一控制库事务提交；崩溃恢复依有效尝试和游标继续，遇到未知副作用仍需人工核对。

条件循环和列表遍历的上限写在各自控制节点中，超限记录控制实例失败并保留此前轮次结果。运行最多尝试100,000次动作；无动作的控制推进分批提交并检查暂停、取消和租约心跳，控制访问总预算为1,000,000次。`NEXT`推进一个实际动作实例，`UNTIL`寻找目标动作的下一次可达出现。受控流程的失败重试须指定执行路径，只失效该出现的失败尝试；从头重跑需创建新的运行。`run.output`默认返回完整聚合，也可按执行路径读取单次结果。

## 任务组合

桌面“任务组合”通过顺序、条件、foreach 和 while/until 结构编排已有任务，同一任务可以有多个引用。组合使用独立启动输入；任务及未绑定步骤输入可映射固定 JSON、组合输入、结构上可用的前序任务 JSON 输出、循环项/索引/状态或分支公共输出。循环内读取当前轮，循环外读取按轮次聚合的任务结果；子任务内部循环投影与组合轮次分开解析。条件外不能直接引用可能未执行的兄弟路径，使用明确的公共输出。命名输出仅接受 JSON，文件不直接跨任务传递。

任务组合页只维护编排、配置和调试。调试前保存当前草稿并检查版本冲突；`sequence.trial` 冻结 TRIAL 模式，子运行均使用完整任务流程调试，允许未确认步骤和流程但保留结构、输入及插件校验。调试记录仅在组合调试区查看，不产生正式执行记录。同一任务的重复或并行调试调用使用独立运行资源。正式执行统一从“执行”的新建入口选择任务或任务组合。组合状态显示就绪、执行中、等待输入、已暂停、需要处理、成功或已取消。等待输入可补参；失败可明确选步骤重试；不确定副作用先提供人工核对依据，再继续。暂停或取消后不会自动启动下一节点；离开页面不终止后台组合。任务/环境/插件与启动快照不一致时，当前节点启动前阻塞。完成节点释放工作进程和资源，结果与历史仍可查询；删除组合定义后，正式运行记录仍在“执行”页保留。


条件在步骤与组合层统一使用有序 cases、唯一 default 及 parallel 布尔字段；关闭并行执行首个匹配，开启并行基于同一批已完成上游事实冻结命中集合。每条路径内继续按定义推进，零命中仅走默认，全部选中路径成功后汇合。公共输出在串行模式为选中值，并行模式按配置顺序以稳定分支 ID 区分；映射求值错误阻止汇合。类型错误或普通缺失引用不会被当作条件不匹配。

步骤级并行仍属于同一 Run，每条路径拥有独立 worker 与资源会话，分支成功按精确执行路径消费；成功兄弟路径不因另一支重试而重做。组合层每次实际任务调用关联独立子 run_id，组合游标、控制实例和任务实例写入控制库；创建子运行及归属绑定共用事务，提交后才启动动作。启动命令 ID 包含执行路径，同一引用的不同轮次不会共用命令。

全局叶动作容量由 execution_capacity 与 CoordinatorPool 共享，普通运行、步骤分支及组合子任务均受限；嵌套控制不占用叶动作槽位。容量不足等待资源。独立失败或待补参路径阻止自身推进，其他已运行路径可完成；汇合等待处理。组合多实例补参/重试/核对须明确 execution_path，子任务内部重试另用 retry_execution_path。暂停、取消、UNKNOWN 核对及回执恢复沿用各自所属运行边界。并行路径不继承外层活跃页面，路径内需要显式建立资源。

## UI与查询

RunCreation负责正式运行的任务/起点/输入选择和create→start流程；组合启动使用保存的编排及按节点分组的启动输入。ExecutionInteraction将独立正式任务运行和正式组合运行合并为顶层列表，隐藏组合子运行及全部调试；支持任务/组合、状态、名称和运行编号筛选，并管理选择、查询缓存与响应代次。组合详情通过共用SequenceExecution展示节点、子执行日志和结果，暂停、取消、继续、补参、重试及核对均路由到所属组合和节点执行路径。删除组合执行清理本次组合及子运行结果，保留定义；运行中先停止。步骤轨道选择只切换展示，执行到该步是单独显式动作。

新建执行按步骤折叠展示全部人工输入，标识必录和可选；任务共享字段单独展示一次，已绑定和环境自动提供的字段由运行时解析。用户可提前填全部、部分或留空启动，填写内容按步骤保存；真正执行到缺少必录项的步骤才进入既有补录。切换任务、环境和线性起点保留草稿，起点之前的步骤值不进入本次运行。

组合启动按调用节点、步骤两层展开，同一任务的多个调用分别填写。`node_inputs` 和 `node_step_inputs` 冻结在组合运行快照中，仅在实际调用时合并，不改变组合定义；循环重复调用使用该节点的预填值。节点已配置的自动映射仍按原语义解析，启动表单不预取前序结果。独立组合启动 Schema 继续使用其现行校验。

步骤调试的“实际执行路径”复用 ExecutionPaths，按所选运行的冻结定义显示实际命中分支和循环轮次；单步仅展示实际尝试动作。线性流程可选起点，含条件或循环的流程从根调试到目标，目标未命中如实显示。

详情查询在页面可见且有变化时刷新；运行日志独立于详情重绘。完整日志按需分页，增量日志默认关闭；run.events.page提供有界游标事件，游标不能跨运行使用。HistoryLoadState控制手动日志的在途与接纳，LogStreamState控制增量状态；离页/隐藏不继续向旧视图写入。
