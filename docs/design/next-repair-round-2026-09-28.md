## P0：执行补参反复弹窗

用户复现：运行到需要补充参数时，点击“稍后再补”，窗口关闭后又被持续弹出，影响操作。

- 核查执行页轮询、同一补参请求的重复触发和弹窗生命周期。
- 同一运行/补参请求被用户暂缓后，不因定时刷新再次自动弹出；保留明确的手动补参入口。
- 以补参请求身份区分旧请求与新请求，不能永久屏蔽同一运行后续的新补参要求。
- 保存输入草稿，防止重复提交、重复续启；迟到响应不能影响另一运行。
- 验收：稍后再补后经过多个刷新周期不重弹，手动打开可正常补充；新请求提示正确，切页和慢请求不产生重复窗口。

### 复核结论（2026-09-29 实测，纠正归因）

用户最初判断为“点外点击穿透到下层按钮”。用 Playwright 在真实工作台上复核后，该机制不成立：

- 弹窗打开时，卡片外任意坐标的命中目标都是 `.q-dialog__backdrop`（`.q-dialog__inner` 是全屏且 `pointer-events:none` 的居中容器），所以单次点击打不到下层按钮。
- 在按下与抬起之间移除弹窗层（模拟执行详情重建补参弹窗），Chrome 会直接取消这次 click：实测事件序列为 pointerdown→backdrop、mousedown→DIV、mouseup→按钮，**没有 click**。

真实症状是弹窗被定时刷新重建后自动重新打开，用户看到“关掉又弹出来”，因此判断为穿透。所以本条关键仍是弹窗生命周期，而不是点击事件：

- `run_inputs.show` 用 `dialog_token` + `is_deleted` 判断“同一补参请求复用旧弹窗”；一旦弹窗元素被销毁（页面重绘），就落回“新建 + `dialog.open()`”分支，表现为重弹。
- `dialog_token` 在弹窗创建成功之前就已写入，构建中途返回（例如身份已变）会留下“token 已更新但弹窗已删除”的状态，下一轮必然重建并重开。

修复仍按本节验收项执行，并需先在现场复现一次确认销毁来源（页面重绘还是身份变化），再落地“暂缓标记 + 草稿”。

## P1：独立调试容器与显式保存

用户已确认的步骤编辑页调整：

- 步骤配置、调试是并列独立容器；日志仍在调试容器下方独立显示，并跟随调试开合。
- 调试更新不重建步骤配置；保存配置后仅同步受影响的调试输入、环境和依赖，保留有效的用户输入和既有结果。
- 旧运行结果继续关联其实际执行版本，配置变化后不能把旧成功当成新版本验证。
- 取消步骤定时自动保存。编辑内容保留为草稿，顶部显示未保存状态并提供“保存”按钮；未保存状态由编辑事件更新，不换成另一种高频全表单扫描。
- 底部只保留“校验内容”和“确认验证”，删除底部“保存步骤”，不再使用“确认验证并保存”文案。
- 切换步骤或离页有未保存内容时提供保存/放弃/取消；保存失败保留草稿。
- 调试、校验、AI 生成与确认涉及当前代码的操作必须明确处理未保存草稿，不能默默使用旧代码。不得为修改文案删除必要的保存/验证保护。
- 范围先限定步骤编辑页；其他页面自动保存单独检查，不一刀切删除。

## P2：Playwright 复杂页面采集增强

现状：扁平元素列表、缺少字段组及 DOM 层级；定位器支持 CSS/role/label/placeholder/frame，没有结构化 within；无专用 checked 读取和断言。已有部分 DOM-path CSS、浮层元素扫描和 match_count，不从零重复建设。

- 增加有范围的定位 within/scope；保留旧字符串和对象定位格式。nth 仅用于已采集的明确顺序证据，不允许猜测索引。
- 增加 radio/checkbox 状态读取和断言，必要时兼顾自定义控件的实际语义。
- 增加局部 DOM 检查：目标、字段标签、父容器、祖先、有限深度子节点及状态；限制体积并标明截断。
- 候选定位器必须用实际执行定位逻辑验证匹配数量；首选失效时提供经过验证的 CSS 备选，避免把 match_count=0 当成可用证据。
- 补齐日期面板“今天”、自定义下拉、body 下浮层和 iframe 的采集覆盖；页面未加载或虚拟化内容不能声称全部采集。

## P2：可选人工操作录制（方案已确认，待开发）

### 插件架构

- TaskWeave 仅负责通用采集会话、身份、生命周期、增量读取、预览和持久化；核心不处理 DOM/点击，也不写 Playwright 专用分支。
- Playwright 插件负责监听人工操作、目标识别、定位证据、页面/frame 归属、局部结构及操作后状态。
- 录制是上下文提供器的可选扩展；不支持录制的旧插件保持原行为。接口职责包含开始、暂停/结束、按游标增量读取、保存后确认消费及丢弃。
- 只监听用户主动开启的采集会话，不默认监听所有浏览器或调试实例；处理新页面、跳转、iframe，停止时释放监听资源。
- 合并连续输入并限制缓冲，避免每次键入回传整页。保存失败保留暂存记录；密码等敏感输入不以明文写入证据或发给 AI。

### 产出与兼容

- 保留当前单次页面快照采集方式，录制可选，不要求用户分别录操作再手动采同一页。
- 一次录制形成上下文组：页面基线、有序操作、目标局部结构、操作前后状态、必要的浮层/新页面变化、可选截图及覆盖说明。
- 开始时采页面基线，操作时记录相关证据，结束并采集时补最终状态；复用同页基线，不逐次保存整页。跳转到新页面建立新基线。
- 区分原始点击节点、关联的可执行控件和业务字段组。例如“开口保单 → 否”不能只保存文字节点“否”；无法可靠关联时明确标注，不猜测。
- 兼容当前预览入口及插件提供的图片/表格展示；“发送上下文预览”仍默认不勾选。页面/操作文本证据、标题和操作说明随上下文提供给 AI，额外预览内容由该开关控制。
- 规划与步骤均支持；录制证据沿用规划生成任务的上下文复制、任务导入导出链路，保护旧上下文和旧任务包兼容。
- 录制是编写证据，不自动生成可靠脚本、不自动回放、不提交业务。

### 验收场景

以本地复杂页面验证多个同名“否”的字段归属、日期“今天”、body 下 dropdown、iframe、新标签页和跳转；检查定位真实唯一、状态验证可靠、预览发送开关有效、导入导出不丢证据，以及大记录量不拖慢采集界面。
