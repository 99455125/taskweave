## 用户已明确的要求

- 首次要求仅保存素材；后续指令已更新为核对原型完整性/逻辑并推进改版，目标是更美观、更适配、操作清晰舒适。原图仍是参考，核心行为冲突先询问。
- 工作台整体参考workbench.png；“最近任务”和“正在执行”两个列表参考局部图，保留每项两个显式按钮，而不是藏进更多菜单。
- 按图记录按钮意图：最近任务为“打开 / 执行”；正在执行为“继续 / 结束”。状态对应的可用性及准确动作语义尚需结合核心核对，不能把执行中再次启动当作继续。
- UI与当前核心逻辑有冲突时，必须先询问用户如何处理；不能为了还原图擅自改核心。
- task ui提供两个方案，本轮仅比较并给建议，未作为用户最终选择。

## 初步比较与组合建议（待用户决定）

方案一擅长任务管理和概览：分类/搜索、任务卡片、任务变量、执行摘要容易浏览；若直接用来编辑，分类栏和卡片会挤占操作空间。

方案二擅长步骤编写：任务列表、步骤列表、编辑区、调试区连贯，减少来回跳页；窄屏若四栏常开会拥挤。

建议同一任务页按工作状态组合：任务概览采用方案一的信息组织；切到步骤详情采用方案二。进入编辑收起分类/标签导航，任务列表可折叠、步骤列表保持窄栏，右侧调试面板按需打开，让源码区域有足够宽度。统一任务标题、概览/步骤详情/执行历史导航及新建执行入口，避免变成两套任务页。

## 后续需要核对的差异（不是本轮实施清单）

这些是从原型与现行模块文档发现的候选问题；实施前逐项核对源码并向用户提出具体选择，现在不替用户决定：

- 执行中的“继续”、等待输入的“继续”、失败重试及UNKNOWN人工核对是不同动作；不能按图片统一再次启动。结束可用性取决于真实资源/运行状态。
- “已发布”、我创建的、收藏、目录/标签、全局搜索、统计口径、配额、账号/通知等展示可能需要新增模型或查询，不能用样例数据假装已支持。
- 规划生成预览里的“8个任务”可能实际对应一个任务的8个步骤；“执行规划”可能混淆生成任务与执行业务。
- 上下文图的直接编辑/删除/拖拽，与现行弹窗草稿、确认一次提交、取消无写入及摘要懒加载需要协调。
- “从选定步骤调试”、重试次数1/3、执行器类型、插件本地安装/升级等需核实支持范围，不能通过视觉改造隐式新增执行策略。
- 原型插件列表及参数只是示例，以真实安装插件和schema为准；市集仍属未来范围。“市集是唯一连接远程服务器的模块”与外部模型API/业务插件访问远端的现状不符，后续需确认文案。
- 设置页的脱敏说明不能扩大成手机号/邮箱/图片等全部自动脱敏保证；环境优先级文案需与当前输入合并规则一致。
- 顶部/侧边主导航、品牌标志和页面命名在各图不完全一致，待素材齐备后统一。
