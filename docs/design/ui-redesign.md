# 工作台 UI 改版设计

日期：2026-09-26。设计负责人：本任务。状态：用户已授权实施，已开始公共主题与布局；业务细则待确认部分保持未决。素材见 [11张原图](ui-prototypes/2026-09-26/README.md)。

## 第一版可点击设计

用户要求先由架构负责人设计 UI。现已形成独立的 [NiceGUI 可点击原型](interactive-prototype/README.md)，第二版覆盖全部八个主页面、任务内步骤编辑和关键弹窗；包含真实渲染截图、窗口适配及交互检查。整体视觉已获认可，本版补齐调试、上下文及其他功能入口，细节待审阅。[功能映射与缺口](interactive-prototype/feature-coverage.md)按 72 组能力对应当前源码。本原型只使用示例数据，不等于产品 UI 已完成或业务规则已确认。

## 目标与授权范围

用户要求界面更美观、更适配不同窗口，操作逻辑清晰、使用舒适；特别重做执行步骤串联样式。任务页结合两套原型。UI与核心冲突必须询问，不以图中示例文案改写运行语义。

主要页面已经足够指导改版，不需要再补一套全量原型。缺少的空态、失败、窄屏、长内容和在途操作状态由本设计补齐。用户已明确新增收藏/分类，不做插件安装升级和账号。其余新增能力及核心交互差异逐项确认，不以原型内容自动扩展范围。

## 技术选择

2026-09-26 用户确认：本轮继续使用 NiceGUI/pywebview，不迁移 React、Electron 或 Tauri。先用现有技术完成界面、适配和交互改版；只有出现经验证无法满足的具体需求时，再评估 UI 技术迁移。通用性与维护性通过模块化组件、公共样式、明确状态归属和模块测试落实，不将框架替换本身作为改版目标。

跨平台与目标机免安装依赖仍是交付要求，需按目标平台验证实际便携包；保留 NiceGUI 不代表这些验收已通过。业务逻辑继续留在 Python 应用层与领域层，UI 经 DesktopController 调用，避免将后续迁移与核心改写绑定。

## 统一结构与视觉

全局顶部导航统一为工作台、规划、任务、执行、插件、市集、环境、设置；右侧保留执行实例、服务日志。不提供账号入口或头像登录占位。通知、全局搜索是否不纳入本轮已列待确认；页面局部搜索只检索该列表。

背景浅灰蓝，内容白底，主色蓝；绿色只表示成功，琥珀色表示等待/待核对，红色表示失败/危险。主操作实心蓝，普通操作描边，更多操作收进菜单。统一字号层级、8px间距、10–12px圆角、轻边框和克制阴影；颜色须伴随图标/文字，不能仅靠红绿区分。

主区域使用可收缩网格而非固定四栏：宽窗支持列表+主体+可选辅助栏；中窗收起任务分类/上下文之外的辅助导航，调试抽屉覆盖或独占；窄窗列表/详情切换，保留返回与选中项。以1440、1280、1024、768宽度检查；外层不得水平溢出，代码/日志/步骤轨道可在自身区域滚动。主要操作与表单不得被抽屉永久遮住。

组件保留清楚的状态归属与dispose。公共视觉样式集中，页面使用同一按钮、状态标签、空态和列表选中态，不把业务状态塞回Workbench。

## 页面方案

| 页面 | 结构与操作 |
| --- | --- |
| 工作台 | 轻量汇总卡+最近任务/活跃执行+待处理入口+最近结果；从现有task/run数据派生，真实空态，不写假增长数字 |
| 规划 | 左侧搜索列表、中间分区配置、右侧按需AI候选；名称/说明、环境插件、上下文、生成记录；操作是生成候选→预览→创建任务 |
| 任务（含概览与步骤编辑） | 一级导航只有“任务”。参考task ui组织任务列表、说明/变量/执行摘要；同页“步骤详情”参考task ui2组合窄步骤列表、编辑主体、调试栏。概览/步骤详情/执行历史是任务内部视图，绝不新增“步骤编辑”一级菜单 |
| 执行 | 明确与task ui及workbench ui使用同一套蓝白卡片、字体、圆角、间距、选中态和按钮样式，不另做一套风格。左运行列表、右选中运行详情；上方筛选/搜索/新建，右侧头部状态与操作，下方步骤轨道、选中步骤详情/结果/历史 |
| 插件 | 左搜索/启用状态列表、右能力与配置说明/加载错误；仅展示真实安装插件，不伪造安装升级按钮 |
| 环境 | 左列表、右环境名称/变量表；明确保存、设为默认、删除。默认与可用性不同，不把“非默认”画成不可用 |
| 设置 | AI、脱敏、执行、工作空间分区；局部导航定位分区；保留保存动作、真实调用提示和API Key兼容规则 |
| 市集 | 明确未开放的占位页，保持视觉一致，不显示虚假可下载内容，不说它是唯一联网模块 |

工作台“最近任务”每项两个按钮：打开、新建执行（用户原话“执行”的准确语义，进入已有确认/输入流程）。草稿不可直接正式执行，入口提示需要确认步骤。列表若以updated_at排序，标题写“最近更新任务”，不把修改时间冒充最近使用时间；不新增访问记录存储。

“正在执行”列表同时承载保留资源/暂停对象时建议命名“活跃执行”。每项保留两操作位置：运行中为查看/结束；暂停为继续/结束；等待输入为填写输入/结束；待核对为核对结果/结束。结束仅在can_end成立时允许，状态有区别不能全部“继续”。失败/已成功且无资源的历史对象移到结果/待处理入口。具体状态转移仍调用原用例，不从UI推断外部操作是否成功。

## 执行步骤轨道（重点）

采用细线串联的编号节点，成功显示小绿勾、当前节点蓝色描边、失败红色图标、UNKNOWN琥珀问号，待执行为灰色编号。步骤标题最多两行，固定合理宽度并提供完整名称提示；节点下简短状态，不让长任务名拉宽所有节点。当前选中节点用浅蓝背景，与业务运行状态分开表示。

横向轨道可滚动；首次进入定位当前/异常步骤，轮询不抢走用户正在查看的历史节点或重置滚动。超多步骤仍保留全部可达，不截掉后半段。窄窗可改为紧凑纵向节点列表，保留顺序与详情入口。

点击节点只切换详情，不执行。详情区显示实际步骤名、状态、尝试次数（无虚构上限）、有效输入、结果、错误与日志；旧尝试可展开且标明失效。成功时“查看结果”，失败时“查看错误/重试”，不确定时先“核对外部业务结果”。继续到此步、从此步重跑等放显式操作菜单/确认，保留现有起点约束和作用范围说明。

运行列表显示任务名、运行时间、环境、状态和已完成步骤数，不绘制每个run的大型步骤条。百分比只表示已完成步骤比例，不声称耗时预测；重跑失效后的步骤不算完成。

## 状态与不变量

- 所有查询经过DesktopController/应用操作。收藏/分类是已授权的新持久化能力，需单独设计元数据、迁移与兼容，不沿用此前“数据库绝不修改”的假设；其余保留任务包/插件契约、worker、锁、命令幂等、输入合并优先级。组织元数据不应使已验证步骤失效或改变执行定义；具体兼容设计在范围确认后形成。
- 保存排队沿用expected_hash/revision；错误保留草稿；离页仍询问继续编辑/舍弃，不能静默丢失或额外保存。
- 上下文组卡片借鉴图中层级/缩略信息，正文预览按需获取；项增删排序先留弹窗草稿，确认整组一次提交，取消不写库。原型中的内联编辑不直接变成自动写库。
- AI候选必须预览/采纳；规划生成8个步骤应写“1个任务，8个步骤”，不暗示8个独立任务。生成不执行业务。
- 正在运行不再提供重复启动；等待输入走原请求ID和补录流程；合法补录提交后离页仍续启原run，迟到UI不得覆盖新页面。
- UNKNOWN不能当普通失败重试；调试保留会话的明确确认例外保持，正式执行不扩大例外。
- 结束资源不改写成功历史；清理和删除保留确认并写清范围；切页dispose只释放页面资源，不结束worker。
- 异步搜索/选中/AI/采集响应绑定原task/step/run和页面代次；刷新不夺焦点、重置表单或丢选择。

## 原型冲突与决策

已确认：收藏、分类需要；插件安装升级不需要；账号不需要。任务界面内部编辑步骤，参考task ui2，不设独立步骤编辑一级菜单。执行界面风格与任务/工作台一致。

本轮已明确提出的待确认项：

1. 收藏/分类建议同时用于规划与任务，各自独立；一级分类、一项一个分类，支持新建/改名/删除，删分类将内容移至未分类；不默认把分类扩为多标签或嵌套文件夹。
2. 工作台两按钮按运行状态变化；节点点击仅查看，执行/重跑独立操作；规划用“生成任务”；上下文仍弹窗确认提交。
3. 页内搜索、真实数据统计及已有执行/调试保留；市集占位；不新增全局搜索、通知、存储配额、自动重试策略或其他执行器类型。

上述为建议，等待用户逐项回答。收藏是否随复制/导入导出携带、分类迁移与持久化的兼容设计还需在明确组织范围后给出，不能擅自更改任务包协议。

本设计对执行状态按钮、规划用词、上下文保存方式提出上述兼容方案，需用户审阅；若要求严格照图改变核心行为，应逐项给出影响再询问，不静默扩需求。调试可用起点须按当前源码核实，不把图中“从选定步骤调试”当核心已支持。

## 验收标准

1. 八个主页面风格、主导航、状态色和按钮层级一致；列表选中、返回和主操作位置稳定。
2. 工作台两列表的双按钮清楚，点击任务执行进入正确任务的现有启动流程，状态不允许重复启动。
3. 执行步骤轨道覆盖1/7/30步、长中文名称、成功/失败/UNKNOWN/待输入；选节点不执行业务，轮询不抢选择。
4. 任务内概览与步骤详情组合可用，没有步骤编辑一级菜单；调试开关不丢草稿，窄屏无外层溢出及主要按钮遮挡。
5. 真实UI覆盖创建任务→保存步骤→调试→确认→新建执行→查看结果，及规划采集取消/确认、候选导入、补录/导航与结束资源。
6. 插件/环境/设置保留既有能力，未支持的原型项不伪装可用，敏感内容遵守现有隐私契约。
7. 按实际改动用module-map预览并运行受影响组件/相关浏览器测试，记录已知基线失败；不运行未授权全量，不删旧断言让改版通过。
8. 收藏/分类按确认范围持久化，重启保留；删分类不删业务内容，不改变步骤确认或运行快照。
9. 最终提供主要页面实际截图与不同窗口检查结果，原型文件本身不充当改版成果。

## 实施边界与后续

设计审阅后形成分步实施计划：公共样式/外壳与工作台、任务/规划/上下文、执行轨道与详情、配置页、针对性验收。可以分段落地但不能把某一页完成当整项完成。新增UI文件登记模块测试映射。只更新受影响模块及本次结果，不同步其他REQ目录。
