### 第 1 批技术边界补充

## 收藏分类已确认规则（用户批准）

任务与规划都支持收藏；分类单层，每个任务/规划最多属于一个分类。删除分类只将其内容移到未分类，不删除任务、规划、步骤、上下文或历史。复制保留原分类；导出任务包不携带本地收藏与分类，导入不依赖来源工作空间的分类标识。

实现须将这些本地组织元数据与执行定义/确认hash分离，不能因收藏或分类变化使步骤确认失效或改变运行快照。旧数据默认为未收藏、未分类，使用增量迁移保留全部原数据。任务和规划的收藏筛选、分类筛选、管理入口按已批准原型接入真实持久化；分类删除与解除关联须同事务完成。共享/分别管理分类的技术结构由负责人依现行存储边界确定，不能引入新的业务层级。复制生成的是独立对象：保留分类，新对象默认不收藏；收藏仍由用户对该对象单独设置。

该项纳入后续实施与验收，不再标记为“范围未获授权”。先完成当前UI2已交审返修，再安排相应代码增量，避免修改冻结审核对象。

## 第 3 批实施裁决

第 2 批已通过 Sol 独立复审并整合。下一批聚焦规划 UI 和已批准的重复导入，收藏分类作为后续独立增量，不混入当前存储变更。

- 规划基础配置只放名称、描述、说明及环境；第二页签统一插件能力选择与上下文素材，保留现有动态采集、暂存确认、revision 和会话保护；第三页签保留生成记录。
- 调用入口统一“大模型api调用”“大模型网页chat调用”；候选预览下、结束采集实例上方保留“导入为任务”。导入后候选和生成记录继续可用，UI处理中禁用重复点击；下一次明确导入创建独立任务。
- `PlanningService.import_generation` 接受有有效候选的 READY/IMPORTED 记录，移除按 imported_task_id 返回旧任务的早退；继续现有候选校验和冻结上下文引用，绝不能读取规划当前素材替换冻结证据。
- 旧 `imported_task_id` 保留为首次导入关联，不覆盖或清空。用增量迁移增加生成记录到导入任务的历史关联表（独立导入ID、generation_id、task_id、时间），回填旧首次关联且迁移重复执行不重复。删除导入任务不能抹掉导入历史；展示时允许任务已删除。仓储负责关联查询与持久化，应用层负责导入编排，不把SQL放进UI。
- 每次成功导入追加一条关联；创建步骤/上下文或记录关联失败时沿用清理新任务的补偿路径，不能删除之前导入任务或修改候选，关联写入与生成状态更新须原子。跨任务文件存储的既有补偿限制如实记录，不声称不存在跨库失败窗口。
- 定向验收：同候选连续两次产生不同task/step/context标识；修改或删除一份不影响另一份；后改规划素材不影响原候选导入；旧IMPORTED记录可再次导入且首次关联不丢；失败无新任务/关联残留；未通过候选不能导入；取消或结束采集不清候选；UI真实按钮与两渠道入口可达。使用临时workspace和本地模型fixture，不调用真实外部模型。
