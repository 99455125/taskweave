# 架构边界

## 产品定位

TaskWeave 是本地开发辅助操作台：定义任务及步骤，执行一步或多步，准备业务现场并允许人工检查。可与自动化测试共享业务动作。

既定使用方式：每人本地安装、本地数据；模板与对应插件代码可分享；环境地址、账号和登录态留在各自机器。AI 在虚拟机外辅助研发，虚拟机内无需 AI。

## 目标结构（功能待实现）

```text
UI / CLI / API
      ↓
application：应用用例
      ↓
core：任务定义 → 步骤编排 → 本次运行及上下文
      ↓  通过插件契约调用
plugins：Playwright / 已验证的自定义业务动作

infrastructure：本地配置、存储、日志，为以上层提供适配
```

| 目录 | 职责 | 不应包含 |
|---|---|---|
| core | 任务、步骤、运行状态、执行与上下文 | Excel / 浏览器 / AI SDK |
| src/taskweave/plugins | 插件协议、注册、能力发现 | 具体业务操作 |
| plugins | 独立能力包及自有依赖 | 对核心内部实现的依赖 |
| application | 用户操作到核心用例的连接 | UI 框架绑定和 SQL |
| infrastructure | 配置、存储、日志实现 | 任务业务编排 |
| apps | 将来 UI / API 的具体入口 | 独立复制执行器 |
| legacy | 历史参考及迁移来源 | 新包的隐式运行依赖 |

## 已定方向

- 一个任务可调用不同插件的动作；自定义动作遵守相同契约。
- 任务/步骤定义与每次运行的状态、输出分离。
- 浏览器会话和角色上下文需支持单步之间延续。
- 导入导出考虑模板版本、插件版本、依赖匹配与本地配置映射。

## 总体设计必须预留的契约

REQ-002 在实现前定义动作引用与执行接口、执行上下文、结果/产物、会话资源和持久化端口。REQ-003 包含执行、存储和调度；REQ-004 详细实现插件管理。核心不能先硬编码浏览器调用，再等插件需求改造。

任务定义预留动作、条件、循环、子流程节点和稳定执行地址。REQ-008 实现控制流，REQ-009 实现拖拽编辑，图形与列表共用模型。

## 步骤生命周期与 AI 扩展

REQ-003 内置步骤 AI 编写服务：描述目标 → 根据项目规范及插件上下文生成 step content → 编辑与试跑 → 反馈修订 → 业务验证 → 保存已验证内容 → 任务执行。

REQ-002 先定义内容、模型端口和插件贡献协议；REQ-004 实现插件贡献机制，REQ-004 提供 Playwright 提示词、API 说明、约束与示例。插件增强同一编写服务，不各自实现 AI。一个 step content 可以调用多个已声明的插件能力。

REQ-005 提供编写调试界面。允许使用 AI 的环境执行生成与修订；虚拟机内只需执行固定内容和试跑，草稿及脱敏反馈可在两侧传递。模型 SDK 在基础设施层适配，核心领域模型不依赖模型厂商。

本期不开发 Excel。每次任务执行时再调用模型的“运行时 AI 动作”仍为独立候选，不能与这里已确定的步骤编写能力混为一谈。

## 待实施验证

REQ-002 已确定步骤/插件接口、总库和任务库 DDL、运行协议，详见 [详细设计](requirements/REQ-002-task-plugin-design/README.md)。真实 UI/Windows worker/离线交付仍需在实现需求中验证。

## 编写方式与插件验证

REQ-003 支持纯手写、AI 生成及两者交替编辑，共用试跑和固化流程。REQ-004 同时实现插件架构与 Playwright 插件，用真实能力检验执行、提示词贡献和资源接口；核心无 Playwright 专用逻辑。

## 存储与步骤保存

不做步骤版本。总库保存任务/步骤当前配置和执行记录；任务专属库默认保存返回的业务输出；文件型产物放任务目录。Playwright 动作可只有状态，不强制返回数据或建表。详见 [存储设计](requirements/REQ-003-task-core/storage.md)。

插件的 AI 扩展包含提示词、上下文、工具、校验、试跑诊断和会话资源，详见 [扩展协议](requirements/REQ-004-plugin-contract/ai-extension.md)。

结果存储由核心统一提供：默认保存步骤输出，管理连接、事务、作用域、索引和清理。插件扩展结果结构、自定义表、转换、解析和预览，不提供数据库保存实现。

## 跨平台客户端

UI 独立窗口内承载本地工作台，自动化 Chromium 单独管理。便携包内置 Playwright/Chromium；NiceGUI/pywebview 的随包 WebView2 方案需通过目标机无安装条件验证，不能由安装器补齐。详见 [打包方案](requirements/REQ-007-v1-release/windows-package.md)。

客户端首期支持 Windows / macOS，共用 NiceGUI 界面与应用服务，pywebview 按平台适配窗口。macOS 使用系统 WebKit，Windows WebView2 依赖仍须满足免安装要求；Playwright 和 Chromium 分平台打包。
