# 发布与集成验收

本页是待执行场景及证据规则，不是本次通过记录。按发布实际范围选择，不要求每次局部修改做全部验收。局部测试见 [测试规则](testing.md)，现有缺陷及平台限制见 [状态](status.md)。

## 基础流程

- [ ] 在干净、匹配的平台准备程序及明确启用的插件，核对版本、依赖和资源。便携目标按禁止安装的条件验证。
- [ ] 独立home导入线性任务，映射本地环境/角色；输入测试参数创建模拟业务单据。
- [ ] 无模型仍可手写、动作表单、调试和确认；AI候选可手动修改，正式固定执行不调用模型。
- [ ] 单步后保留浏览器供人工检查，继续到目标/提交；第二次运行状态和数据独立。
- [ ] 回溯输入、单号、定义快照、尝试、日志、截图及结果文件；业务结果在任务库，控制库只管记录和引用。
- [ ] 无结果操作不强制创建业务库；文件receipt等必要元数据不误判。插件自定义表/结果迁移按真实声明验证。

## 异常和兼容

- [ ] 重复命令/真实UI确认只产生一次有效提交；同ID不同body拒绝。缺插件、版本冲突、参数错误在执行业务前提示。
- [ ] 超时/worker崩溃根据receipt恢复；无确证标UNKNOWN，人工核对后再决定，不承诺外部系统天然exactly-once。
- [ ] 已人工提交的业务不盲目重做；前置重跑使对应下游输出失效，不读取其他run或陈旧证据。
- [ ] 必填输入在正确步骤暂停、取消不失败、补录按原模式续启；导航/迟到AI/旧采集弹窗不串写其他目标。
- [ ] 活跃运行不覆盖定义；修改后重新确认当前步骤，MANUAL与TRIAL分清，不要求不存在的步骤版本树。
- [ ] 迁移/备份恢复/复制导入中途失败、路径边界和清理隔离有可复現证据。

## 分享、平台及将来能力

完整分享要检查凭据、浏览器状态、DB及绝对路径，当前JSON包并不自动保证源码/默认值/采集原文无秘密。第二台Windows、断网环境及真实业务适配各需独立验收。平台硬门槛见 [Windows清单](windows-portable.md)，后续zip/控制流/图形编排场景见 [路线](roadmap.md)；未交付范围不得勾选。

用户说明、插件开发契约、已知限制、依赖/版本清单应随实际产物完整提供。冻结环境安装任意wheel不是现有承诺。没有真实内网业务时，模拟成功只记模拟成功。

## 记录方法

每项记源码/包版本、环境、前置数据、命令/操作、预期、实际结果、证据路径及限制。区分文档检查、单元测试、本地fixture、真实浏览器、真实账号与目标实机；不同组有重叠不累加为唯一通过数。未运行标未验证，旧日志与签署不能替代本次运行。

历史验收概要及逐文件出处保存在 [知识迁移台账](archive/req-knowledge-migration.md)，只有追溯历史签署/原日志才需打开原需求，不把历史证据复制成当前测试通过。
